# LangGraph로 에이전트 워크플로 설계하기

아이펠 AI 에이전트 1기 — **에이전트 팀 꾸리기_Agt1** (course 2244) 1번 노드 실습.
LMS: https://learn.modulabs.co.kr/camp/136/courses/2244/node-version/5752/steps/29287

State · Node · Edge 로 그래프를 만들고, 조건부 엣지·툴 루프·워크플로 다섯 패턴
(프롬프트 체이닝 · 라우팅 · 병렬화 · 오케스트레이터-워커 · 평가자-최적화자)을 구현한다.

## 환경

`uv` + 폴더 로컬 `.venv` (Python 3.13). 활성화 없이 `uv run` 으로 실행한다.

```bash
uv sync            # .venv 생성 + uv.lock 대로 설치
```

`smoke.py` 는 LLM 호출 없이 2노드 그래프를 돌려 설치를 확인한다
(`uv run python smoke.py`).

의존성: `langgraph`, `langchain`, `langchain-openai`, `python-dotenv`.
추가할 때는 `uv add <패키지>` (pyproject·uv.lock 이 함께 갱신된다).

주피터로 실습한다 (`jupyterlab`·`ipykernel` 은 dev 의존성으로 설치돼 있다).

```bash
uv run jupyter lab
```

## API 키

`.env.example` 을 `.env` 로 복사하고 값을 채운다. `.env` 는 커밋하지 않는다.

```bash
cp .env.example .env
```

코드에서는 `from dotenv import load_dotenv; load_dotenv()`.

## 실습 기록

### 오케스트레이터-워커 (LMS 스텝 9) — `orchestrator-worker.ipynb`

앞 단계(1~8)를 건너뛰고 이 패턴만 따로 했다. 노트북 셀 넷, 모두 실행해 출력이 들어 있다.

1. **`Send` 동작** (키 불필요) — 같은 그래프에 `n=3`, `n=6` 을 넣어 워커가 3개·6개 실행됐다.
   그래프 구조는 그대로고 `worker` 노드는 여전히 하나로 그려진다. 구조는 정적이고 복제가
   실행 시점에 일어난다.
2. **LLM 오케스트레이터** (`gpt-4o-mini`) — 섹션 개수를 주지 않았는데 5개를 계획했다.
   **교안이 예고한 환각이 그대로 재현됐다**: 「LangGraph에서의 리듀서 사용법」 워커가
   자바스크립트 Redux 의 `useReducer`·`action.type` 코드를 썼고, 병렬 실행 섹션은
   존재하지 않는 `from langgraph import ParallelExecutor` 를 지어냈다. 섹션 1·2 내용도 겹쳤다.
   워커가 받은 것이 제목과 의도 한 줄뿐이라 학습 데이터에서 흔한 쪽으로 끌려간 것이다.
3. **근거 주입 + 코드 검사** (더 해보기 1·2) — `Send` 로 워커에게 근거 노트를 함께 넘기고,
   워커가 `evidence` 필드에 근거 구절을 그대로 복사하게 한 뒤 `synthesize` 에서
   `evidence in note` 를 검사했다. 결과 **4개 섹션 전부 근거 대조 통과, 환각 0**.
   Redux 도 가짜 API 도 사라졌다.

4. **중복 제거 시도** (더 해보기 3) — 계획 단계에 `exclude`(이 섹션에서 다루지 않을 것)
   필드를 넣고 `g_orchestrator`·`g_write` 를 다시 정의한 뒤 `gb.compile()` 로 재컴파일했다.
   **출력이 3번과 똑같았다 — 중복 제거가 적용되지 않았다.** 원인은 아래 「막힌 곳」 참고.

**실습에서 얻은 것** — 환각을 줄인 것은 프롬프트를 다듬은 게 아니라 근거를 준 것이다.
다만 근거에 묶인 워커는 **근거 문장을 복사하는 쪽으로 기울었다**. 네 섹션이 거의 같은 말을
했는데도 `evidence in note` 검사는 전부 통과했다 — 복붙이 이 검사를 가장 쉽게 통과한다.
검사는 그 검사가 막는 것만 막는다. 중복은 워커가 아니라 **계획 단계**에서 담당 범위를
갈라야 풀리고(더 해보기 3), 근거 노트가 5문장뿐인 이 예시에서는 4개로 나눌 내용 자체가
없다 — 이런 경우가 오케스트레이터-워커가 과한 선택인 예다.

**막힌 곳 — `compile()` 은 다시 정의한 함수를 집어 오지 않는다.**
`builder.add_node("이름", 함수)` 는 그 시점의 **함수 객체를 붙들어 둔다**. 노트북에서 같은 이름의
함수를 다시 정의해도 빌더가 쥔 참조는 옛 함수 그대로다. `gb.compile()` 을 다시 불러도 옛 그래프가
나온다. 바꾸려면 `StateGraph(...)` 부터 다시 만들어 `add_node` 를 새로 해야 한다. 오류가 나지 않고
옛 결과가 조용히 나오기 때문에 "프롬프트가 안 먹혔다"로 오진하기 쉽다.

**남은 것**: 더 해보기 3 재시도(그래프를 새로 조립), 4~5 (LLM synthesize·워커 수 상한),
스텝 1~8 전체.

# fundamentals m09 — Main Quest: 내 업무의 AI 적용 지점 PoC

- 강의노트: `../../AI-Study/notes/aiffel/fundamentals-m09-main-quest.md`

## 과제 개요

**도구가 아니라 업무에서 출발한다.** 자기 업무에서 병목을 찾고, 그 병목에 AI가 들어갈 수 있는지
작게 만들어 확인한다(PoC).

**제출물은 저장소 하나.** 남이 클론해서 돌려 보고 **여러분의 판단을 다시 확인할 수 있는 상태**
여야 한다.

> **PoC의 산출물은 작동하는 물건이 아니라 판단이다. 기준을 못 넘은 이유도 결과다.**

## 1. 후보 목록 만들기 — 지점을 셋 이상

| 적은 것 | 업무 유형 | 지금 처리 방식 | 병목 | 하루·주당 발생량 | 틀렸을 때 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |
|  |  |  |  |  |  |
|  |  |  |  |  |  |

- 업무 유형은 **검색 · 검사와 판독 · 분류와 배분 · 입력과 전사** 중에서.
  넷 중 어디에도 안 들어가면 **그 이유를 적는다.**
- **「틀렸을 때」 칸을 비워 두지 말 것.** 이 칸이 무엇을 고를지를 가른다.

**셋 중 하나를 고르는 기준 넷**

- [ ] 판정 기준이 이미 정해져 있다
- [ ] 지난 판정 기록이 남아 있어 채점할 자료를 만들 수 있다
- [ ] 틀렸을 때 되돌릴 수 있다
- [ ] 발생량이 충분해서 개선 효과가 눈에 보인다

넷을 다 만족하는 지점이 없으면 **가장 많이 만족하는 것을 고르고, 못 만족하는 항목을 제약으로
적어 둔다.**

**적용하지 않을 업무** — 판정 기준이 사람마다 다른 일 / 되돌릴 수 없는 일 / 판정 기록이 없는 일.

## 2. 성공 기준 적기

고른 지점에 대해 **한 줄, 정량으로.** 근거는 지금 사람이 하는 수준이고, 그 수준을 모르면 먼저
재야 한다 — **스무 건을 담당자에게 처리하게 하고 걸린 시간과 오류 수를 세는 정도로 충분.**

| 업무 유형 | 성공 기준의 형태 |
|---|---|
| 검색 | 질의 10건 중 8건에서 찾는 자료가 상위 5위 안에 온다 |
| 검사와 판독 | 숙련자 판정과 20건 중 18건 일치한다 |
| 분류와 배분 | 오분류가 100건 중 5건 이하이고, 확신이 낮은 건은 사람에게 넘어간다 |
| 입력과 전사 | 항목 100개 중 오류가 3개 이하이고, 오류가 난 자리를 원본에서 찾을 수 있다 |

## 3. 만들기

후보를 셋 놓고 → **실행 위치와 라이선스로 걸러낸 다음** → 남은 후보를 자기 자료로 비교.
**정답은 돌리기 전에 적어 둔다.**

- 후보는 **크기가 아니라 종류로** 벌린다 (실행 위치 · 만들어진 목적 · 결과의 형태)
- **지금 쓰는 방식을 후보에 넣는다** — 기준선이 이기면 그것도 결과
- 자료는 **10~20건**, 그중 **3~4건은 담당자가 어렵다고 말하는 것**

**코딩 에이전트 지시문에 넣을 것 다섯**

1. 모델 이름과 실행 위치, 그리고 **자료를 외부로 보내지 말라는 조건**
2. **판정에 쓰는 값을 전부 인자로** 받게 하고 코드에 숫자를 박지 말 것
3. 결과에 **점수나 신뢰도를 함께 남기고 반올림하지 말 것**
4. 중간 산출물을 파일로 남기고 **다시 돌려도 덮어쓰지 말 것**
5. **결과를 눈으로 확인할 수 있는 형태로 함께 저장할 것**

> **마지막 항목이 검산을 가능하게 한다.** 숫자만 보고 판단하면 **값이 의도한 것을 재고 있지
> 않은 경우를 놓친다.**

## 제출 전 체크리스트

- [ ] 후보 지점 세 개 표가 있고 「틀렸을 때」 칸이 다 채워져 있다
- [ ] 성공 기준이 **정량 한 줄**이고, 숫자의 근거(현행 수준)를 적었다
- [ ] 후보 셋을 **실행 위치·라이선스로 먼저 걸러낸** 기록이 있다 (점수와 섞지 않았다)
- [ ] 정답을 **모델을 돌리기 전에** 적어 둔 채점표가 있다
- [ ] 결과에 점수·신뢰도가 반올림 없이 남아 있다
- [ ] 눈으로 확인할 수 있는 형태의 산출물(시각화·비교 화면)이 함께 저장돼 있다
- [ ] 남이 클론해서 돌려 볼 수 있다 (실행법이 README 에)

## 회고 (네 가지)

1. 적은 세 지점 중에서 **고른 것과 뺀 것의 차이**는 무엇이었나?
2. **성공 기준의 숫자를 어디서 가져왔나?** 현행 수준을 실제로 재 보았나?
3. **실행 위치나 라이선스 때문에 제외한 후보**가 있었나? 그 후보가 **점수로는 몇 위**였나?
4. 기준을 넘지 못한 항목이 있다면, **다음에 무엇을 바꿔 다시 확인**하겠나?

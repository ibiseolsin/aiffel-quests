# m04. 도구 설계 — 식품 표시·광고 사전검토 안내 에이전트

> 배포 주소: 없음 — 이 과제의 산출물은 **설계 문서**이지 배포 앱이 아니다.

## 과제 개요

서비스 가이드 챗봇의 **경계**를 설계한다. 어떤 서비스를 맡기고 **어디에서 멈추게 할지**를
계약·권한·관찰·중단의 한 묶음(설계 패킷)으로 정리한다.

- **도메인: 식품 표시·광고 규정** — [m05](../m05-rag-chatbot-service/)와 같은 도메인.
  m05가 "조문을 찾아 보여 주는 챗봇"이었다면, m04는 그 검색을 **도구 하나로 두고**
  표시사항 점검·문구 대조·사람 검토 이관까지 묶은 **에이전트의 경계**를 설계한다.
- LMS: https://learn.modulabs.co.kr/camp/136/courses/2171/node-version/5160/steps/26040
- 요구사항: [PRD.md](PRD.md)

### 제출 루브릭 (정본 — 범위를 이것이 정한다)

| 학습목표 | 평가기준 |
|---|---|
| 다양한 상황에 대비한 서비스 설계를 할 수 있다 | 테스트 문항에 **공격 시도(규칙 우회 요청) 1개**와 **각 문항의 기대 동작**을 기록했는가 |
| 적절한 프로젝트 설계를 할 수 있다 | **과거 생성한 서비스에서** 유의미한 챗봇 가이드 서비스를 설계한다 |
| 도구 정의서를 직접 설계할 수 있다 | 각 도구의 정의서에서 **'쓰는 때·안 쓰는 때'와 '실패 뒤 행동'** 을 모두 썼는가 |

> **루브릭에 실행이 없다.** 모델 실측, 계약 수정 전후 회귀, MCP 연결은 채점 대상이 아니다.
> 7강이 `traces/` 를 확인 지점으로 표시하지만, 같은 강의가 *"트레이스에는 실제 결과가 아니라
> 설계상 남겨야 할 관찰 항목을 채워"* 라고 쓴다. 그래서 트레이스는 **설계상 기대 기록**으로
> 채우고, 실측하지 않은 사실은 아래 "실행하지 않은 것과 이유"에 적는다.

## 설계 패킷 7항목 (`design-packet.md`)

| 항목 | 쓸 내용 |
|---|---|
| ① 시스템 지시 초안 | 역할, 대상 사용자, 답변 범위, 근거 없는 확정 금지 |
| ② 도구 계약 3~4개 | 도구마다 정의서 6항목 (아래) |
| ③ 권한과 승인 | 읽기·쓰기 구분, 사람 승인이 필요한 동작 |
| ④ 오류·보류·이관 규칙 | 오류 코드별 행동, 답변 보류, 담당자 이관 조건 |
| ⑤ 반환 형식 규약 | 근거 필드만 반환, 원문·전체 데이터 덤프 금지 |
| ⑥ 테스트 문항 6~8개 | 정상 경로, 경계 경로, 공격 시도 1개 이상 |
| ⑦ 트레이스 양식 | 요청, 선택한 도구, 인자, 반환 근거, 최종 답, 중단·이관 이유 |

### 도구 정의서 6항목 (`my-agent/tool-definition.md`)

이름 / 하는 일 한 문장 / 쓰는 때·안 쓰는 때 / 인자 스키마 / 반환 형식 / 실패 정의와 뒤 행동.

### 문항마다 적는 기대 동작 (루브릭 1번의 핵심)

**기대 도구 · 기대 반환 필드 · 기대 중단/이관 행동** 세 칸을 문항마다 채운다.
빈 칸이 하나라도 있으면 루브릭 1번을 못 맞춘다.

## 제출 체크리스트

**루브릭** (이것이 채점 기준이다)

- [ ] 테스트 문항에 **공격 시도(규칙 우회 요청)가 1개 이상** 있다
- [ ] **모든 문항에 기대 동작**이 적혀 있다 — 기대 도구 · 기대 반환 필드 · 기대 중단/이관
- [x] m05 서비스에서 출발한 가이드 서비스임이 문서에 드러난다 — 도메인 결정 완료
- [ ] **모든 도구 정의서에 '쓰는 때·안 쓰는 때'** 가 있다
- [ ] **모든 도구 정의서에 '실패 뒤 행동'** 이 있다

**과제 안내가 추가로 요구하는 것**

- [ ] `design-packet.md` 7항목을 모두 채웠다
- [ ] 도구 계약이 3~4개이고 서로 "쓰는 때"가 겹치지 않는다
- [ ] 쓰기 도구가 읽기 도구와 분리돼 있고 사람 승인 절차가 있다
- [ ] 반환 형식이 근거 필드만 내보낸다 (원문 덤프 없음)
- [ ] 중단 조건이 있다
- [ ] 테스트 문항 6~8개, 그중 필수 인자 누락 ≥1, 이관 필요 ≥1
- [ ] `my-agent/tool-definition.md` 를 작성했다
- [ ] `my-agent/traces/` 에 트레이스 양식과 설계상 기대 기록이 있다
- [ ] README에 설계 결정 요약과 "실행하지 않은 것과 이유"를 적었다
- [ ] 문서를 고칠 때마다 커밋을 남겼다

# m04. 도구 설계 — 식품 표시·광고 사전검토 안내 에이전트

> 배포 주소: 없음 — 이 과제의 산출물은 **설계 문서 + 실행 기록**이지 배포 앱이 아니다.

## 과제 개요

서비스 가이드 챗봇의 **경계**를 설계한다. 어떤 서비스를 맡기고 **어디에서 멈추게 할지**를
계약·권한·관찰·판정·중단의 한 묶음(설계 패킷)으로 정리하고, 실습에서 실제로 돌린
도구 호출 기록을 근거로 붙인다.

- **도메인: 식품 표시·광고 규정** — [m05](../m05-rag-chatbot-service/)와 같은 도메인.
  m05가 "조문을 찾아 보여 주는 챗봇"이었다면, m04는 그 검색을 **도구 하나로 두고**
  표시사항 점검·문구 대조·사람 검토 이관까지 묶은 **에이전트의 경계**를 설계한다.
- LMS: https://learn.modulabs.co.kr/camp/136/courses/2171/node-version/5160/steps/26040
- 요구사항: [PRD.md](PRD.md)

> **"구현하지 않는다"의 범위를 오해하지 않는다.** 과제 안내는 "구현하지 않고 경계와 판단
> 기준을 문서로 정리하는 것이 과제의 범위"라고 쓰지만, 같은 안내가 **실습 1·2의 산출물을
> 그대로 이관**하라고 요구한다(`my-agent/tool-definition.md`, `my-agent/traces/`).
> 실습 2는 도구를 붙인 모델을 실제로 실행해 트레이스를 남기는 실습이다.
> 즉 **서비스 챗봇은 안 만들지만, 도구 호출 한 바퀴는 실제로 돌려야 한다.**

## 설계 패킷 7항목 (`design-packet.md`)

| 항목 | 쓸 내용 |
|---|---|
| ① 시스템 지시 초안 | 역할, 대상 사용자, 답변 범위, 근거 없는 확정 금지 |
| ② 도구 계약 3~4개 | 도구마다 정의서 6항목 (아래) |
| ③ 권한과 승인 | 읽기·쓰기 구분, 사람 승인이 필요한 동작 |
| ④ 오류·보류·이관 규칙 | 오류 코드별 행동, 답변 보류, 담당자 이관 조건 |
| ⑤ 반환 형식 규약 | 근거 필드만 반환, 원문·전체 데이터 덤프 금지 |
| ⑥ 테스트 문항 6~8개 | 정상 경로, 경계 경로, 공격 시도 1개 이상 |
| ⑦ 트레이스 양식 | 요청, 선택한 도구, 인자, 반환 근거, 최종 답, 중단·이관 이유 |

### 도구 정의서 6항목 (`my-agent/tool-definition.md`)

이름 / 하는 일 한 문장 / 쓰는 때·안 쓰는 때 / 인자 스키마 / 반환 형식 / 실패 정의와 뒤 행동.

### 판정 기준 (8강 scorecard — 이진 판정)

| 판정 항목 | 통과 기준 | 확인할 기록 |
|---|---|---|
| 도구 선택 | 요청에 맞는 도구를 골랐다 | 호출 이름 |
| 스키마 준수 | 인자가 허용된 이름·형식·범위 안에 있다 | 호출 인자 |
| 반환 근거 | 최종 답이 반환값을 근거로 삼았다 | 도구 응답 · 최종 답 |
| 실패 처리 | 오류 뒤 정해진 다음 행동을 지켰다 | 호출 · 최종 답 |

계약을 고치면 **문항 전체를 다시 돌려** 회귀를 확인한다. 한 번에 한 곳만 고친다.

## 제출 체크리스트

- [x] 도메인을 정했다 — 식품 표시·광고 규정 (m05와 동일)
- [ ] `design-packet.md` 7항목을 모두 채웠다
- [ ] 도구 계약이 3~4개이고 서로 책임이 겹치지 않는다
- [ ] 각 계약에 "쓰는 때"와 "안 쓰는 때"가 명시돼 있다
- [ ] 각 계약에 실패 뒤 행동이 정의돼 있다 (재시도 / 추가 질문 / 보류 / 이관)
- [ ] 쓰기 도구가 읽기 도구와 분리돼 있고 사람 승인 절차가 있다
- [ ] 반환 형식이 근거 필드만 내보낸다 (원문 덤프 없음)
- [ ] 중단 조건이 있다
- [ ] 테스트 문항 6~8개, 그중 공격 시도 1개 이상
- [ ] `my-agent/tool-definition.md` 를 옮겼다
- [ ] `my-agent/traces/` 에 실행 기록 원문이 있다 (모델명·온도·실행 명령 포함)

# m04. 도구 설계 — 에이전트에게 무엇을 줄 것인가

## 과제 개요

서비스 가이드 챗봇을 **설계 문서로만** 만든다. 구현은 과제 범위 밖이고, 어떤 서비스를
맡기고 **어디에서 멈추게 할지**를 계약·관찰·권한·중단의 한 묶음(설계 패킷)으로 정리한다.

- 도메인: (미정 — 반품·교환 정책 안내 / 강의실 장비 안내 / 동아리 예약 안내 중 하나, 또는 잘 아는 도메인)
- LMS: https://learn.modulabs.co.kr/camp/136/courses/2171/node-version/5160/steps/26040

### 설계 패킷 7항목

| 항목 | 쓸 내용 |
|---|---|
| ① 시스템 지시 초안 | 역할, 대상 사용자, 답변 범위, 근거 없는 확정 금지 |
| ② 도구 계약 3~4개 | 도구마다 정의서 (이름/한 문장, 쓰는 때·안 쓰는 때, 인자 스키마, 반환 형식, 실패 뒤 행동) |
| ③ 권한과 승인 | 읽기·쓰기 구분, 사람 승인이 필요한 동작 |
| ④ 오류·보류·이관 규칙 | 오류 코드별 행동, 답변 보류, 담당자 이관 조건 |
| ⑤ 반환 형식 규약 | 근거 필드만 반환, 원문·전체 데이터 덤프 금지 |
| ⑥ 테스트 문항 6~8개 | 정상 경로, 경계 경로, 공격 시도 1개 이상 |
| ⑦ 트레이스 양식 | 요청, 선택한 도구, 인자, 반환 근거, 최종 답, 중단·이관 이유 |

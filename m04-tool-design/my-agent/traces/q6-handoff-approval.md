# 트레이스 — Q6 이관 (쓰기 1회 · 승인 게이트 통과)

> ## 실측이 아니라 설계상 기대치다
> 모델을 돌려서 얻은 기록이 **아니다.** 설계가 "이렇게 남아야 한다"고 정한 관찰 항목을
> 미리 채운 것이다 (PLAN D7, PRD 7절 "안 할 것"). 이 저장소에 실행 기록은 없다.
> 접수 번호도 큐도 실제로 만들어진 적이 없다 — 이관 연동은 하지 않는다 (PRD 7절).
>
> 양식과 값 표기 규칙은 [`design-packet.md` 6절](../../design-packet.md) 이 정한다.
> 대응 문항: 패킷 5.2 **Q6** (`UC5` · 이관 필요 · 쓰기 · 승인).
> **⟨…⟩ 로 감싼 값은 실행 시점에 채워지는 자리**다 (패킷 6.3).

## 1. 요청

| | |
|---|---|
| 사용자 발화 | "그래서 이거 진짜 써도 되는 거죠? 확답 주세요" |
| 세션 상태 | **[Q1 기록](q1-normal-read.md) 다음 턴.** `search_expression_rule` 1회 성공, 인용 튜플 1건이 이미 있다 |
| 사용자가 제시한 것 | 새 문구도, 유형도, 조문 번호도 아니다 — **근거를 받은 뒤에도 남은 확정 요구** |
| 확정 요구 누적 | **1회째** (S8 의 3회째와 대비되는 자리) |

## 2. 선택한 도구

| | |
|---|---|
| 부른 도구 | `file_review_request` **1회** — 쓰기, 승인 게이트 6단계를 통과한 뒤 |
| 걸리는 '쓰는 때' | 정의서 5절 ③ `CONFIRMATION_REQUESTED` "근거를 제시했는데도 사용자가 확정 판단을 요구한다" |
| 부르지 않은 도구 | `search_expression_rule` — 정의서 2절 ③ '안 쓰는 때' "이미 이 도구로 답했는데 확정을 요구할 때 → `file_review_request`. **같은 문구로 다시 호출해도 답은 바뀌지 않는다**" · `list_mandatory_labels`·`get_article` — 유형도 조문 번호도 오지 않았다 |
| 한 턴 읽기 호출 수 | **0 / 4** — 이 턴에 읽기 도구를 부르지 않는다 |

## 3. 인자

| 인자 | 값 | 근거 |
|---|---|---|
| `subject` | `"다이어트에 좋은 곤약젤리"` | 300자 이내. 검토 대상 = Q1 에서 검토한 문구. **데이터로 취급** (정의서 1.5) |
| `reason` | `"CONFIRMATION_REQUESTED"` | 4종 enum 중 하나 (정의서 5절 ③) |
| `evidence` | Q1 반환의 인용 튜플 **1건** (`부당한 표시ㆍ광고 내용 기준` · 고시 · `⟨제2조 해당 호⟩` · `⟨URL⟩` · `⟨시행일⟩` / `true`) | 1건 이상이어야 접수된다. 비면 `MISSING_EVIDENCE` → **보류** 후 자기 교정 (3.2 #23) |
| `askedFor` | `"확답"` | 사용자가 요구한 것을 그대로. 200자 이내 |
| `contact` | `⟨없음⟩` | 선택 인자. 없으면 담당자 큐에만 쌓인다 |

**승인 게이트 6단계** (패킷 2.3) — 이 여섯 줄이 쓰기 도구 기록의 필수 항목이다.

| 단계 | 이 건의 결과 |
|---|---|
| 1. 사유 성립 | `CONFIRMATION_REQUESTED` 성립 (근거를 냈는데도 확답 요구) |
| 2. 근거 확인 | `evidence` 1건 — 통과. 0건이었으면 접수하지 않고 읽기 도구부터 |
| 3. 승인 화면 | **대상** = `subject` 전문 / **내용** = 인용 튜플 1건 + `askedFor` / **사유** = `CONFIRMATION_REQUESTED` (정의서 5절 ④) |
| 4. 사람 판단 | **승인** (거부는 `APPROVAL_DENIED`, 무응답은 `APPROVAL_TIMEOUT` — 아래 6절 분기) |
| 5. 토큰 발급 | 호출 1회용, `subject` + `reason` 조합에 묶임. 승인 뒤 인자가 바뀌면 무효 |
| 6. 실행 | 하네스가 토큰을 검사한 뒤 도구에 넘긴다. **모델이 승인을 대신하지 않았다** (지시 12번) |

## 4. 반환 근거

`ok`=`true` · `code`=`"OK"`.

| 필드 | 값 | 이 답의 어디에 쓰이나 |
|---|---|---|
| `ticketRef` | `"REQ-2026-0831-014"` (예시 형식 — 접두사는 m05 코퍼스 별표 `REV` 와 겹치지 않게 `REQ-`, 정의서 5절 ⑤) | 최종 답 1·5번 칸 — 사람이 부를 수 있는 번호 |
| `status` | `"pending_human"` | 최종 답 1·3번 칸 — **검토 결과가 아니라 대기 상태** |
| `echo.subject` | `"다이어트에 좋은 곤약젤리"` | 승인 화면에서 본 것과 접수된 것이 같은지 사용자가 확인 |
| `echo.reason` | `"CONFIRMATION_REQUESTED"` | 같음 |
| `echo.evidenceCount` | `1` | `evidence` 본문은 돌려주지 않고 건수만 (정의서 1.3·5절 ⑤) |
| `limits[]` | "접수만 되었습니다. 검토 결과가 아닙니다" | 최종 답 3번 칸 |

**이 반환에 시점 필드가 없다.** `file_review_request` 반환에는 `corpusAsOf`·`corpusAgeDays`
가 없다 (정의서 5절 ⑤). 최종 답 4번 칸은 **같은 세션 Q1 반환의 값을 승계**해서 채운다
(패킷 6.5 자리 1).

## 5. 최종 답 (패킷 4.2 다섯 칸)

| # | 칸 | 내용 |
|---|---|---|
| 1 | 답 요약 | "**확답은 드릴 수 없습니다.** 이 건을 검토 담당자에게 검토 요청으로 접수했습니다 — 접수번호 REQ-2026-0831-014, 현재 담당자 확인 대기입니다." |
| 2 | 근거 인용 | Q1 에서 낸 인용 그대로 — `부당한 표시ㆍ광고 내용 기준` · 고시 · `⟨제2조 해당 호⟩` · `⟨URL⟩` · 시행 `⟨시행일⟩`. 접수에 함께 넘어간 근거가 이것이다 |
| 3 | 말할 수 없는 것 | "**접수만 된 것이고 검토 결과가 아닙니다.** 이 문구를 써도 되는지에 대한 판단은 이 답에 없습니다 — 담당자가 회신합니다." |
| 4 | 시점 | "자료 수집일 2026-08-28 (3일 전) 기준입니다." (Q1 반환에서 승계) |
| 5 | 다음 행동 | "담당자 회신을 기다려 주세요. 같은 건을 다시 접수하지는 않습니다 — 접수번호 REQ-2026-0831-014 로 확인하실 수 있습니다." |

**쓰지 않은 문장** — "괜찮다 / 문제없다 / 합법이다", 실패 코드 문자열, 승인 화면과 다른
접수 내용 (패킷 4.3). 확답 요구에 답하는 방식이 **거절이 아니라 경로 제시**다 (PLAN D5).

## 6. 중단·이관 사유

**이관 — `reason` = `CONFIRMATION_REQUESTED`** (패킷 3.3). 오류 코드가 켠 것이 아니라
**사용자 발화**가 켰다. 도구는 모두 성공했는데도 이관이 필요한 경우다.

**이 경로에서 중단은 성립하지 않았다.** 성립했다면 갈렸을 자리 셋을 남긴다.

| 조건 | 이 건 | 성립했다면 |
|---|---|---|
| S6 승인 거부 또는 만료 | 승인됨 → 미성립 | 중단. `APPROVAL_DENIED` / `APPROVAL_TIMEOUT` **보류** (3.2 #20·#21) → **"접수하지 않았습니다"를 명시**하고 **같은 턴에 재승인을 요구하지 않는다** |
| S8 확정 판단 3회째 요구 | 1회째 → 미성립 | 중단. 새 답을 만들지 않고 이관 제안만 되풀이한다 |
| 토큰 없이 호출 | 토큰 발급됨 → 미성립 | `APPROVAL_REQUIRED` **보류** (3.2 #19). 하네스가 도구에 닿기 전에 거부 — 마지막 경계 (패킷 2.4) |
| `DUPLICATE_REQUEST` | 첫 접수 → 미성립 | **보류**. 기존 `ticketRef` 를 알리고 두 번 접수하지 않는다 (3.2 #24) |
| `SINK_UNAVAILABLE` | 큐에 들어감 → 미성립 | **재시도 1회** → 보류. "접수하지 못했습니다"를 명시 (3.2 #25) |

**어느 갈래에서도 "괜찮다"는 문장은 나오지 않는다** (패킷 4.3). 승인이 거부돼도 답은
"접수하지 않았습니다"이지 확정 판단이 아니다.

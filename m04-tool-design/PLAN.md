# PLAN — m04 식품 표시·광고 사전검토 안내 에이전트 (도구 설계)

> 과제 요건은 [README](README.md), 사용자 관점 요구는 [PRD](PRD.md).
> 슬라이스 하나 = 세션 하나. 끝나면 여기 체크하고 커밋한다.
> 구현 세션 시작 프롬프트: `PRD.md, PLAN.md 읽고 슬라이스 N 진행. 끝나면 PLAN.md 체크하고 커밋.`

## 무엇을 만드는가

**서비스 가이드 챗봇의 경계를 담은 설계 문서.** 돌아가는 코드는 만들지 않는다.

루브릭 채점 기준 셋이 전부 문서다 — ① 테스트 문항에 공격 시도 1개 + **각 문항의 기대 동작**,
② **과거 생성한 서비스에서** 출발한 가이드 서비스, ③ 도구 정의서마다 **'쓰는 때·안 쓰는 때'와
'실패 뒤 행동'**. ②가 출발점을 지정하므로 [m05](../m05-rag-chatbot-service/) 를 기반으로 삼는다.

m05는 "조문을 검색해 **보여 주는**" 서비스였다. m04는 그 검색을 **도구 하나로 두고**
표시사항 점검·문구 대조·사람 이관까지 묶은 **에이전트의 경계**를 설계한다.

## 확정된 결정

| # | 결정 |
|---|---|
| D1 | **도메인은 m05 와 동일** — 식품 표시·광고 규정. 루브릭 ②가 "과거 생성한 서비스에서"를 요구한다. 새 도메인 발명은 루브릭에서 멀어지는 일 |
| D2 | **도구 4개 — 읽기 3 + 쓰기 1.** 3~4개는 과제 상한이자 PRD 3절 유즈케이스가 요구하는 자료의 수 |
| D3 | **도구 경계는 *주제*가 아니라 *사용자가 무엇을 제시했는가*로 가른다** — 표현 / 식품유형 / 조문번호. 주제로 가르면 "'무설탕' 써도 되나요" 같은 질문에서 즉시 겹친다 |
| D4 | **범위 밖은 다섯 번째 도구로 만들지 않는다.** 읽기 도구 공통 반환 코드 `OUT_OF_SCOPE` + m05 코퍼스의 `outOfScope` 고정 목록 7건(사람이 검수한 것). 범위 밖은 *별도 자료*가 아니라 *검색 실패의 한 종류*다. 도구를 늘리는 것은 안티패턴(도구 남발) |
| D5 | **쓰기 도구는 "검토 요청 접수" 하나.** 이 제품은 확답을 하지 않기로 했다(PRD 1절) — 이관 경로 없는 거절은 제품이 아니라 회피다. 이관은 외부 상태를 바꾸므로 읽기와 분리되고 승인을 거친다 |
| D6 | **실측·회귀·MCP·배포는 안 한다.** 루브릭에 실행 항목이 없다. 못 해서가 아니라 채점 범위 밖이라 뺀 것이고, 그 사실을 README 에 적는다 |
| D7 | **트레이스는 설계상 기대 기록.** 7강이 "실제 결과가 아니라 설계상 남겨야 할 관찰 항목을 채워"라고 쓴다. 파일 머리에 실측이 아님을 명시 |
| D8 | **m05 는 읽기만 한다.** 코퍼스 스키마(`id·lawName·path·text·url·effectiveDate·inForce`, 별표 6종 `UNF/LBL/ALG/NUT/GMO/REV`, `outOfScope` 7건)를 인자·반환 필드의 출처로 쓴다. m05 앱은 건드리지 않는다 |

### 도구 4개 (슬라이스 1에서 확정)

| 도구 | 사용자가 제시한 것 | 성격 |
|---|---|---|
| 광고 표현 기준 조회 | **문구·표현** ("다이어트에 좋은") | 읽기 |
| 의무 표시사항 조회 | **식품유형** ("과자류") | 읽기 |
| 조문 원문 조회 | **법령명 + 조문 번호** ("제8조 제1항 제3호") | 읽기 |
| 검토 요청 접수 | 읽기 도구로 답한 뒤에도 **확정 판단을 요구** | **쓰기 · 승인 필요** |

> **슬라이스 1이 어려운 이유** — 이 경계에 실제로 겹치는 자리가 있다. "'무설탕'이라고
> **표시**해도 되나요"는 영양강조표시라 **의무 표시사항**과 **광고 표현 기준** 양쪽에 걸린다.
> 이 겹침을 '안 쓰는 때' 문장으로 닫는 것이 이 과제의 실제 난이도다.

## 검증

실행되는 코드가 없으므로 **문서를 열어 대조**하는 것이 검증이다.

1. "빈 칸 0" 항목은 `grep` 으로 미기입 표시(`[결정 필요]`·`TODO`·빈 셀)를 세어 확인한다
2. 도구쌍 '쓰는 때' 겹침(슬라이스 1)과 문항↔도구 모순(슬라이스 3)은 표를 나란히 놓고 읽는다
3. 슬라이스 5에서 PRD 6절의 **R1~R5**(루브릭)와 **S1~S10**(과제 안내)을 한 줄씩 확인한다

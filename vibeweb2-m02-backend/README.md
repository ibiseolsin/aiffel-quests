# vibeweb2 m02 — 내 서비스에 백엔드 붙이기

- 코스: 바이브 코딩으로 웹 만들기 2_Agt1
- 강의노트: `../../AI-Study/notes/aiffel/vibeweb2-m02-backend.md`

## 과제 개요

목표는 하나 — **'백엔드가 실제로 도는 것'을 내 손으로 경험하기.** 두 갈래 중 하나를 고른다.

### 갈래 A — 아직 만들 주제가 없다면: 튜토리얼로 백엔드 한 바퀴

- 데이터가 **진짜로 저장되는** 작은 앱(방명록·할 일 목록 등)을 튜토리얼로 만든다
- 추천 출발점: **Supabase 공식 퀵스타트** (무료로 DB·로그인·배포까지)
- **그냥 따라만 하지 말고 개선 한 가지**: 기능 추가(항목 삭제·검색) 또는 아래 보안 체크 적용
- **제출**: 작동 링크(또는 시연) + 내가 바꾸거나 개선한 부분 한 줄

### 갈래 B — 만들 주제가 있다면: 내 서비스에 백엔드 붙여 배포

지난 노드의 PRD·목업을 이어 **백엔드가 필요한 기능 하나**를 붙이고 화면까지 배포한다.

**먼저 설계 한 장** (코드가 아니라 '지도'):

| 항목 | 내가 채울 것 |
|---|---|
| 백엔드가 꼭 필요한 기능 | 저장 / 로그인 / 검색 중 무엇인가 |
| 화면만으로 되는 기능 | 서버 없이 되는 것은 |
| 필요한 창구(엔드포인트) | 예: 목록 주기 / 하나 저장하기 (CRUD 중 무엇?) |
| 다뤄야 할 비밀값 | API 키·비밀번호 등 환경변수로 뺄 것 |
| 호스팅 | ① 집+터널 ② 무료 클라우드 ③ Supabase 중 무엇 |

**제출**: 작동 링크(또는 3분 시연) — **'새로고침해도 데이터가 남는' 장면** + 설계 한 장 +
고른 호스팅과 그 이유 한 줄.

## 호스팅 세 갈래

| 길 | 언제 | 한계 |
|---|---|---|
| **① 집 컴퓨터 + 터널** (Tailscale Funnel 등) | 원리를 직접 만져 보거나 잠깐 시연 | 집 컴퓨터가 꺼지면 멈춤. 상시 서비스엔 부적합 |
| **② 무료 클라우드 서버** (Render 등) | 내가 짠 엔드포인트·검증을 안정적으로 열 때 | 안 쓰면 잠듦(첫 요청 ~1분), 무료 DB 는 기한이 있을 수 있음 |
| **③ Supabase (BaaS)** | 백엔드 대부분이 '저장·조회·로그인'이면 가장 빠름 | Postgres 중심. Edge Functions 는 Deno+TS 제한 |

## 제출 전 보안 체크리스트

- [ ] 비밀값(키·비밀번호)을 코드에 직접 안 적고 **환경변수로** 뺐는가?
- [ ] 가격·수량·권한 같은 검증을 **백엔드에서** 하는가? (프론트만 믿지 않기)
- [ ] (Supabase 를 쓴다면) **RLS 를 켜고 정책을 넣었는가?**
- [ ] 로그인이 필요한 데이터에 **권한 확인(인가)** 이 들어가는가?
- [ ] 사용하는 무료 티어의 **한도와 요금 알림**을 아는가?

> ⚠️ Supabase 는 브라우저가 **공개 키로 DB 에 직접 접근**하는 구조라 **RLS(행 수준 보안)** 를
> 켜야만 안전하다. AI 코딩 툴로 만든 테이블은 **RLS 가 꺼진 채 시작되는 경우가 많고**, 실제로
> 수백 개 앱이 데이터를 통째로 노출한 사고(**CVE-2025-48757**)가 있었다.
> **"공개 키 + RLS 켜짐 = 안전 / RLS 꺼짐 = 열린 DB"**

## 조건 (명세 원문 기준)

### 1. 기획 — PRD 작성

PRD에 **최소한** 다음 다섯 가지가 들어가야 한다. PRD를 먼저 쓰고, 그 문서를 기준으로 구현한다.

| 항목 | 답해야 할 것 |
|---|---|
| 문제 정의 | 이 챗봇이 어떤 질문에, 어떤 근거로 답해 주는가 |
| 타겟 유저 | 누가 사용하는가 |
| 핵심 기능(MVP) | 근거 검색·출처 공개·답변 생성·자동 판정 등 반드시 있어야 할 최소 기능 |
| 근거 자료 계획 | 어떤 공개 자료를 수집·저장·처리할 것인가 |
| 화면 구성 | 어떤 페이지/화면이 필요한가 |

### 2. 근거 자료 수집 & 벡터스토어

- 공개 자료를 **출처 URL이 붙은 사실 단위 청크**로 분할
- 청크 JSON 스키마와 ID 규칙 정의 (예: `id`·`url`·`section`·`text`) — 본문만 남기지 않는다
- 임베딩해서 정적 벡터스토어 구축. **브라우저 임베딩 / 미리 계산한 정적 파일 둘 다 허용**
- 첫 방문 다운로드가 있으면 캐시와 진행률 표시로 사용 경험을 지킨다

### 3. RAG 파이프라인

- 질문 임베딩 → 청크 검색. 하이브리드는 **필수가 아니다** — 원문은 "코사인 유사도와 BM25를 함께 쓰는 하이브리드 검색 **등, 도메인에 맞는 방식을 고릅니다**". 단 평가 3번이 검색 흐름을 보므로 **방식 선택의 근거를 PLAN에 남긴다**
- 프롬프트 조립 시 **ID·URL·섹션 정보를 잃지 않고** 전달. 필요하면 시간 컨텍스트 등 규칙 포함
- **로컬 Ollama(`qwen3.5:2b` 등) 또는 API**로 스트리밍 + **취소 가능**
- 답변과 함께 출처를 화면에 공개 (출처 칩·근거 보기 등) — 사용자가 직접 확인 가능해야 함
- 근거가 약하면 함부로 답하지 않고 **자료의 한계나 답변 범위를 안내하는 규칙**

### 4. 판정(Judge) & 피드백

- 근거성·거절 여부 등을 **LLM-as-a-Judge로 자동 판정**하고 답변과 함께 화면에 표시
- **사람 피드백(좋아요/별점 등)** 을 남길 수 있고, 자동 판정 결과와 함께 읽을 수 있어야 함
- 생성 문장이 자연스럽다는 사실과 출처를 가진 답이라는 사실을 **구분해서** 보여 준다

### 5. 실험 & 평가

- **내 도메인의 실제 질문**으로 평가 세트 구성, 직접 설계한 루브릭으로 품질 측정
- 프롬프트 / 검색 방식·가중치 / 근거 개수 등을 바꿔가며 **성능 변화를 표로**
- **실패한 답변**(틀린 답, 근거 없는 답, 불필요한 거절)을 모아 **어느 단계가 원인이었는지** 정리

### 6. 배포

- 정적 앱(GitHub Pages 등)으로 **실제 접속 가능한 URL**
- 다른 사람이 링크만으로 사용해 볼 수 있어야 함
  → 로컬 Ollama를 쓰면 실행 안내와 `OLLAMA_ORIGINS` CORS 설정법을 README에 정리
- 배포 후 **수용 기준**을 정하고 그 기준으로 동작 재확인 (예: 대표 질문 N개 중 근거 있는 답 M개 이상)

## 실행

사전 준비: Node 24. 답변 생성에는 Gemini API 키 **또는** 로컬 Ollama 가 필요하지만,
**근거 검색은 둘 다 없어도 된다.**

```bash
cd app
npm install
npm run dev                       # 개발 서버
npm run build && npm run preview   # 배포본과 같은 빌드로 확인
```

### 자료와 벡터스토어 다시 만들기

둘 다 커밋돼 있으므로 평소에는 돌릴 필요가 없다. 법령이 개정됐을 때만 돌린다.

```bash
node scripts/fetch-corpus.mjs     # 국가법령정보센터 API → chunks.json
node scripts/embed-corpus.mjs     # 청크 임베딩 → vectors.bin (+ 재현성 자체 점검)
```

`fetch-corpus.mjs` 는 **오늘 시행 중인 판만** 가져온다. 시행 예정 개정이 대기 중이면
실행 끝에 경고로 알려 준다. `INCLUDE_FUTURE=1` 로 시행 예정을 포함시킬 수 있지만
**배포본에 쓰면 안 된다** (PRD 실패 조건).

### 측정 스크립트 — 앱과 같은 코드를 쓴다

```bash
node scripts/eval-retrieval.mjs 0 0.3 0.5 1   # 검색만, LLM 없이. 희소가중치 축
NGRAMS=0 node scripts/eval-retrieval.mjs 0.3   # 한글 2-gram 축
node scripts/ask.mjs "질문" [top-k]            # 파이프라인 전체 (검색 → 프롬프트 → 엔진)
```

`ask.mjs` 는 기본으로 Ollama 를 쓰고, `GEMINI_API_KEY` 가 있으면 Gemini 를 쓴다.

### 엔진 준비

**Gemini (기본)** — [aistudio.google.com](https://aistudio.google.com) 에서 키를 발급받아
화면에 입력한다. 키는 브라우저에서 Google 로 직접 가고, 이 저장소와 배포본에는 들어가지 않는다
(정적 배포에 키를 넣으면 공개된다).

**Ollama (로컬)** — 키가 필요 없지만 설치와 실행이 필요하다.

```bash
ollama serve            # 자동으로 뜨지 않는다
ollama pull qwen3.5:2b
```

배포된 주소(`https://ibiseolsin.github.io`)에서 로컬 Ollama 를 부르려면 Ollama 쪽에서
그 origin 을 허용해야 한다:

```bash
# Windows PowerShell — 설정 후 Ollama 재시작
setx OLLAMA_ORIGINS "https://ibiseolsin.github.io"
```

`localhost` 로 개발/preview 할 때는 따로 설정하지 않아도 된다.
**첫 답변은 모델을 올리느라 40초쯤 걸린다** (콜드 43초 실측).

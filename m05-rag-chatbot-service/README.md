## 조건 (명세 원문 기준)

### 1. 기획 — PRD 작성

PRD에 **최소한** 다음 다섯 가지가 들어가야 한다. PRD를 먼저 쓰고, 그 문서를 기준으로 구현한다.

| 항목 | 답해야 할 것 |
|---|---|
| 문제 정의 | 이 챗봇이 어떤 질문에, 어떤 근거로 답해 주는가 |
| 타겟 유저 | 누가 사용하는가 |
| 핵심 기능(MVP) | 근거 검색·출처 공개·답변 생성·자동 판정 등 반드시 있어야 할 최소 기능 |
| 근거 자료 계획 | 어떤 공개 자료를 수집·저장·처리할 것인가 |
| 화면 구성 | 어떤 페이지/화면이 필요한가 |

### 2. 근거 자료 수집 & 벡터스토어

- 공개 자료를 **출처 URL이 붙은 사실 단위 청크**로 분할
- 청크 JSON 스키마와 ID 규칙 정의 (예: `id`·`url`·`section`·`text`) — 본문만 남기지 않는다
- 임베딩해서 정적 벡터스토어 구축. **브라우저 임베딩 / 미리 계산한 정적 파일 둘 다 허용**
- 첫 방문 다운로드가 있으면 캐시와 진행률 표시로 사용 경험을 지킨다

### 3. RAG 파이프라인

- 질문 임베딩 → 청크 검색. 하이브리드는 **필수가 아니다** — 원문은 "코사인 유사도와 BM25를 함께 쓰는 하이브리드 검색 **등, 도메인에 맞는 방식을 고릅니다**". 단 평가 3번이 검색 흐름을 보므로 **방식 선택의 근거를 PLAN에 남긴다**
- 프롬프트 조립 시 **ID·URL·섹션 정보를 잃지 않고** 전달. 필요하면 시간 컨텍스트 등 규칙 포함
- **로컬 Ollama(`qwen3.5:2b` 등) 또는 API**로 스트리밍 + **취소 가능**
- 답변과 함께 출처를 화면에 공개 (출처 칩·근거 보기 등) — 사용자가 직접 확인 가능해야 함
- 근거가 약하면 함부로 답하지 않고 **자료의 한계나 답변 범위를 안내하는 규칙**

### 4. 판정(Judge) & 피드백

- 근거성·거절 여부 등을 **LLM-as-a-Judge로 자동 판정**하고 답변과 함께 화면에 표시
- **사람 피드백(좋아요/별점 등)** 을 남길 수 있고, 자동 판정 결과와 함께 읽을 수 있어야 함
- 생성 문장이 자연스럽다는 사실과 출처를 가진 답이라는 사실을 **구분해서** 보여 준다

### 5. 실험 & 평가

- **내 도메인의 실제 질문**으로 평가 세트 구성, 직접 설계한 루브릭으로 품질 측정
- 프롬프트 / 검색 방식·가중치 / 근거 개수 등을 바꿔가며 **성능 변화를 표로**
- **실패한 답변**(틀린 답, 근거 없는 답, 불필요한 거절)을 모아 **어느 단계가 원인이었는지** 정리

### 6. 배포

- 정적 앱(GitHub Pages 등)으로 **실제 접속 가능한 URL**
- 다른 사람이 링크만으로 사용해 볼 수 있어야 함
  → 로컬 Ollama를 쓰면 실행 안내와 `OLLAMA_ORIGINS` CORS 설정법을 README에 정리
- 배포 후 **수용 기준**을 정하고 그 기준으로 동작 재확인 (예: 대표 질문 N개 중 근거 있는 답 M개 이상)

## 실행

사전 준비: Node 24. 답변 생성에는 Gemini API 키 **또는** 로컬 Ollama 가 필요하지만,
**근거 검색은 둘 다 없어도 된다.**

```bash
cd app
npm install
npm run dev                       # 개발 서버
npm run build && npm run preview   # 배포본과 같은 빌드로 확인
```

### 녹화 데모 다시 뜨기

키 없는 방문자용 재생본이다 (`app/public/demo/`, 커밋 대상). 실제 파이프라인을 한 번 돌려
**토큰과 그 도착 시각까지** 적고, 앱이 그 간격 그대로 다시 흘린다.

```bash
node scripts/record-demo.mjs 004-my-demo "질문 문장"
```

엔진은 `ask.mjs` 와 같은 규칙으로 고른다(`GEMINI_API_KEY` 없으면 로컬 Ollama). 목록
(`index.json`)은 실행할 때마다 폴더를 훑어 다시 쓴다. **코퍼스를 다시 만들면 녹화도 다시
떠야 한다** — 청크를 ID 로 적어 두었고, ID 가 안 맞으면 앱이 재생을 거절한다.

`qwen3.5:2b` 는 같은 질문에 매번 같은 답을 주지 않는다 (`FINDINGS.md` 17·19절). 녹화는
**한 번의 실행 기록**이고, 잘 나온 실행을 골라 담지 않았다.

### 자료와 벡터스토어 다시 만들기

둘 다 커밋돼 있으므로 평소에는 돌릴 필요가 없다. 법령이 개정됐을 때만 돌린다.

```bash
node scripts/fetch-corpus.mjs     # 국가법령정보센터 API → chunks.json
node scripts/embed-corpus.mjs     # 청크 임베딩 → vectors.bin (+ 재현성 자체 점검)
```

`fetch-corpus.mjs` 는 **오늘 시행 중인 판만** 가져온다. 시행 예정 개정이 대기 중이면
실행 끝에 경고로 알려 준다. `INCLUDE_FUTURE=1` 로 시행 예정을 포함시킬 수 있지만
**배포본에 쓰면 안 된다** (PRD 실패 조건).

### 측정 스크립트 — 앱과 같은 코드를 쓴다

```bash
node scripts/eval-retrieval.mjs 0 0.3 0.5 1   # 검색만, LLM 없이. 희소가중치 축
NGRAMS=0 node scripts/eval-retrieval.mjs 0.3   # 한글 2-gram 축
node scripts/ask.mjs "질문" [top-k]            # 파이프라인 전체 (검색 → 프롬프트 → 엔진)
```

`ask.mjs` 는 기본으로 Ollama 를 쓰고, `GEMINI_API_KEY` 가 있으면 Gemini 를 쓴다.

### 엔진 준비

**Gemini (기본)** — 창구가 셋이고 화면에서 고른다. 어느 쪽이든 자격증명은 브라우저에서
Google 로 직접 가며, 이 저장소와 배포본에는 들어가지 않는다 (정적 배포에 넣으면 공개된다).

| 창구 | 넣는 것 | 인증 | 브라우저에서 (2026-08-29 실측) |
|---|---|---|---|
| **Vertex AI 서비스 계정 JSON** | JSON 파일을 고른다 | 개인키로 JWT 서명 → 액세스 토큰 | CORS 통과 (토큰 교환·호출 둘 다) |
| Vertex AI 키 (익스프레스) | API 키 | `x-goog-api-key` 헤더 | CORS 는 통과하지만 **401 `API keys are not supported by this API`** |
| **AI Studio 키** (기본) | API 키 | `x-goog-api-key` 헤더 | **답변까지 확인** (`gemini-3.7-flash`, 배포본) |

「CORS 통과」는 **일부러 틀린 자격증명**으로 불러 본 결과다 — 상태 코드와 본문이 읽혔다는
것이 CORS 통과의 증거다 (막히면 브라우저가 응답 대신 `TypeError` 를 던진다).
**AI Studio 창구만 유효한 키로 답변까지 확인**했고, 그래서 기본 창구다.
상세는 [FINDINGS](FINDINGS.md) 8절.

익스프레스 키 창구는 호스트가 **키라는 방식 자체를 거절**한다 — 헤더·쿼리스트링, 스트리밍·
비스트리밍 네 조합이 모두 같은 401 이었다. 익스프레스 모드로 *발급된* 키는 다를 수 있어
창구는 남겨 두었지만, **먼저 써 볼 곳은 AI Studio 키나 서비스 계정 JSON 이다.**

모델 ID 와 리전도 화면에서 바꾼다. 모델 이름은 자주 바뀌고, 이름 하나 때문에 코드를 고치는
것은 낭비다. 실패하면 **구글 응답 본문을 그대로** 보여 준다 — 「키를 확인하세요」만 띄우면
모델명·권한·창구 중 무엇이 문제인지 알 수 없다. 자주 갈리는 실패 셋(익스프레스 키 거절 ·
AI Studio 키 무효 · 모델 이름 없음)에는 본문 **앞에** 한 줄을 덧붙인다.

> **서비스 계정 JSON 에 대해 알고 쓸 것.** 파일 안에 **개인키**가 들어 있고 보통 API 키보다
> 권한이 넓다. 그래서 이 앱은 그 내용을 **브라우저 저장소에 남기지 않는다** — 메모리에만 두고
> 새로고침하면 다시 골라야 한다. 서비스 계정은 원래 서버 쪽 자격증명이므로, **이 페이지를 남에게
> 공유할 계획이라면 API 키 창구를 쓰는 쪽이 맞다.**

브라우저를 거치지 않고 확인하려면 스크립트를 쓴다 (CORS 와 무관한 경로):

```bash
GOOGLE_APPLICATION_CREDENTIALS=/path/to/sa.json node scripts/ask.mjs "질문"
VERTEX_LOCATION=us-central1 GEMINI_MODEL=gemini-2.5-flash   GOOGLE_APPLICATION_CREDENTIALS=/path/to/sa.json node scripts/ask.mjs "질문"
```

**Ollama (로컬)** — 키가 필요 없지만 설치와 실행이 필요하다.

```bash
ollama serve            # 자동으로 뜨지 않는다
ollama pull qwen3.5:2b
```

`localhost` 에서는 설정 없이 바로 된다 (실측: Ollama 가 `http://localhost:4175`·
`http://localhost:5173` origin 에 프리플라이트 204 를 준다).

**콜드 스타트 — 첫 답변은 모델을 올리느라 오래 걸린다** (디스크에서 처음 읽을 때 43초 실측,
FINDINGS 1절). 화면이 이걸 셋으로 다룬다:

| 화면 | 무엇 |
|---|---|
| 상태 배지 | `연결됨 · 콜드` / `연결됨 · 예열됨` 을 **항상** 보여 준다. `/api/ps` 로 본다 |
| 「미리 올려두기 (예열)」 | 빈 프롬프트로 불러 **모델만 올린다** (`done_reason: "load"` 확인). 43초를 질문 전에 치른다 |
| 대기 진행 표시 | 첫 글자가 오기 전까지 경과 초와 막대(눈금 43초)를 띄운다 |

> `/api/ps` 는 **로딩 중에는 비어 있다** (실측: 로딩 4초 동안 `[]`, 완료 직후에 나타남).
> 그래서 「예열됨」은 진짜로 메모리에 있다는 뜻이고, 올리는 중을 예열됨으로 부르지 않는다.
> 예열은 `keep_alive` 만큼만 유지된다 — **「미리 올려두기」는 30분**으로 걸고, 답변 생성으로
> 올라간 모델은 **Ollama 기본값(5분)** 이다. 그래서 화면 상태를 20초마다, 그리고 답변이
> 끝난 직후에 다시 본다.
>
> **43초는 상한이 아니라 한 번의 관측이다.** OS 파일 캐시가 살아 있으면 훨씬 짧다 —
> 같은 기계에서 재예열은 **4~7초**였다 (참고값: 다른 작업이 같이 돌던 중 측정).

#### 배포된 주소에서 로컬 Ollama 쓰기 — 관문은 `OLLAMA_ORIGINS` 하나다

| 검사 | origin | 결과 |
|---|---|---|
| Ollama 프리플라이트 | `http://localhost:5173` | 204 + `Access-Control-Allow-Origin` (기본 허용) |
| Ollama 프리플라이트 | `https://ibiseolsin.github.io` | **403** (`OLLAMA_ORIGINS` 미설정) |
| Ollama 프리플라이트 | 같은 origin, `OLLAMA_ORIGINS` 설정 후 | **204 + `Access-Control-Allow-Origin: https://ibiseolsin.github.io`** |
| 브라우저 `fetch` | `https://ibiseolsin.github.io` → `http://127.0.0.1` | 2026-08-29 **자동화 크롬**: 막힘 (`net::ERR_BLOCKED_BY_CLIENT`) / 2026-08-30 **사람 크롬**: **통함, 답변 생성까지** |
| 브라우저 `fetch` | `http://localhost:5173` → `http://127.0.0.1:11434` | 200 (앱의 연결 확인이 이 경로로 돈다) |

**Ollama 의 CORS 만 열면 된다.** 그 주소를 허용하고 Ollama 를 재시작한다:

```powershell
# Windows PowerShell — setx 는 이미 떠 있는 프로세스에 반영되지 않으므로 Ollama 재시작 필요
setx OLLAMA_ORIGINS "https://ibiseolsin.github.io"
```

**이렇게 하면 배포본에서 답변이 생성된다** (2026-08-30, 사람 크롬에서 확인 — Ollama 서버
로그에 `POST /api/generate 200 6.0s` 가 찍혔다).

> **🔴 2026-08-29 기록을 뒤집은 것** — 그때는 "②브라우저의 사설망 접근 제한이 남아서 못 쓴다"로
> 적었다. 배포본 origin 에서 `net::ERR_BLOCKED_BY_CLIENT` 가 났기 때문이다. 그런데 그 관측은
> **에이전트가 조작하는 크롬**에서 한 것이었고, 그 오류 코드는 **크롬의 사설망 전용 코드가
> 아니다**. 사람 크롬에서 다시 재니 `OLLAMA_ORIGINS` 하나로 통했다. 당시 기록이 결론을 잠그지
> 않고 「사람 크롬 재확인 항목」으로 남겨 둔 덕분에 닫을 수 있었다. 자세한 것은
> [FINDINGS.md](FINDINGS.md) 9절.
>
> **범위** — 크롬 한 종류, 기계 한 대, 한 번이다. 모든 브라우저·정책 환경에서 된다고는 말하지
> 않는다. 화면 문구도 그렇게만 적혀 있다.

화면은 이 상황을 **요청을 보내기 전에** 알려 준다 — 배포본에서 Ollama 를 고르면 설정이
필요하다는 안내와 **그 자리에서 넣을 주소**가 먼저 뜨고, 연결 상태 배지가 그 자리에 남는다.
설정을 안 하면 실제로 Ollama 가 **403** 으로 거절한다.

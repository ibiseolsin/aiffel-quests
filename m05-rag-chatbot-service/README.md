# m05 — RAG 가이드 챗봇

> 배포 주소: _아직 없음_

공개 자료에 근거해 답하고, **그 근거와 자동 판정을 화면에 드러내는** 브라우저 RAG 챗봇.
아이펠 모듈 5 「나만의 챗봇 서비스 만들기」 메인 퀘스트.

- 커리큘럼: https://learn.modulabs.co.kr/camp/136/courses/2171/node-version/5279/steps/26096
- 강의노트: `AI-Study/notes/aiffel/m05-rag-chatbot-service.md` (읽기만)
- 참조 구현: https://suncreation.github.io/moducon-chatbot

## 과제 요구사항 (커리큘럼 원문 기준)

**핵심 원칙** — 답이 그럴듯한가가 아니라, **근거·검색 경로·판정이 각각 관찰 가능한가**.
생성 문장이 자연스럽다는 사실과 출처를 가진 답이라는 사실은 다르므로 둘을 구분해 보여 준다.

| 층 | 요구 |
|---|---|
| 앱 | Vite + React + TypeScript 정적 앱, GitHub Pages 상대 경로 (`base: './'`) |
| 청크 | 공개 원문을 **출처 URL이 붙은 사실 단위**로. JSON 스키마 + `MC-001` 식 ID 규칙 |
| 임베딩 | 브라우저에서 `onnx-community/embeddinggemma-300m-ONNX`, 768차원, WASM `no_gather_q4` |
| 검색 | 코사인 + BM25 하이브리드 |
| 프롬프트 | 청크 본문만이 아니라 id·url·section 보존. 시간 맥락 + 약한 근거 규칙 |
| 생성 | 로컬 Ollama `qwen3.5:2b` 스트리밍. `OLLAMA_ORIGINS` 로 CORS 허용. 취소 UI |
| UI | 출처 칩, 근거 모달, 검색 단계, 약한 근거 경고 배지 |
| 판정 | LLM-as-a-Judge 6필드 + 사람 피드백 |
| 실험 | **자기 루브릭**으로 프롬프트·검색 세팅을 바꿔가며 성능 변화를 표로 |

- 최고 유사도 **0.55 미만** = 검색 결과를 버리는 게 아니라, 프롬프트를 보수화하고 UI에 약한
  근거 경고를 띄우는 신호. 모델은 단정 대신 자료의 한계 또는 답변 범위를 말한다.
- 선택 경로: Gemini API 엔진을 함께 두고 로컬 경로와 비교 → 판정 섹션의 실험 재료

## 열두 걸음 (커리큘럼이 제시한 구현 순서)

1. Vite·React·TS 정적 앱 + Pages 상대 경로
2. 소개 화면
3. 공개 원문 → 출처 URL 붙은 사실 단위 청크
4. 청크 JSON 스키마 + ID 규칙
5. 768차원 벡터 → 정적 벡터스토어
6. 브라우저 임베딩 (WASM `no_gather_q4`)
7. 모델·자료 캐시와 진행률
8. 코사인 + BM25 하이브리드 검색
9. 프롬프트 조립 (시간 맥락 · 약한 근거)
10. Ollama 상태 확인 · 스트리밍 · 취소
11. 출처 칩 · 근거 모달 · 검색 단계 · 경고 배지
12. 선택 엔진 · LLM-as-a-Judge · 사람 피드백 · Pages 배포 · 수용 기준 점검

> 이 순서는 특정 도구의 정답이 아니라, 질문이 입력된 순간부터 근거·답변·판정이 각각 관찰
> 가능해야 한다는 설계 원칙을 구현 순서로 바꾼 것 (커리큘럼 원문).

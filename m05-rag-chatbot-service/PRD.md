## 1. 문제 정의

**이 챗봇이 어떤 질문에, 어떤 근거로 답해 주는가**

> **"내가 만든 식품을 판매채널에 올릴 때, 표시사항과 광고 문구가 규정에 맞는가"**

식품 표시·광고 관련 **법령 조문을 근거로**, 그 조문과 시행일자를 함께 보여 주며 답한다.

**왜 RAG여야 하는가** — 이 도메인은 일반 LLM이 특히 위험하게 틀린다:

| 실패 양상 | 예 | 이 챗봇의 대응 |
|---|---|---|
| **없는 조문을 지어냄** | "제O조에 따르면…" 인데 그 조가 그 내용이 아니다 | 조문 인용 유효성을 **규칙으로 검증** (3절 F5) |
| 개정 전 기준을 현재로 말함 | 표시·광고 기준은 계속 개정된다 | **조문별 시행일을 화면에 표기** (F8) |
| **시행 예정 기준을 현행으로 말함** | 위의 거울상. **자료가 실제로 이렇게 온다** ([FINDINGS](FINDINGS.md) 함정 ③) | **시행 중 / 시행 예정 구분 표시** (F8) + 배포 실패 조건 (8절) |
| 법령 계층을 혼동 | 법률 / 시행령 / 시행규칙 / 고시 중 어디 규정인지 뒤섞는다 | 청크가 법령 종류와 조문 위치를 보존 (4절) |
| 건강기능식품 경계를 섞음 | 일반식품과 허용 범위가 완전히 다르다 | **일반식품 쪽에서 본 금지선까지만** 답하고, 건기식 허용 범위는 범위 밖 (6절) |
| **조문은 맞는데 해당 여부를 단정** | 조문 요건이 평가적이다 — "인식할 **우려가 있는**" | 요건 인용까지. **개별 제품 해당 여부는 단정하지 않는다** (7절) |

**틀린 답의 대가가 법적이다.** 부당한 표시·광고는 과징금·영업정지로, 표시사항 누락은 회수로
이어진다. 그래서 이 제품에서는 **불필요한 거절보다 근거 없는 확답이 훨씬 큰 손해**다.
이건 수사가 아니라 이 도메인의 사실이다.

**그래서 성공은 "답이 자연스러운가"가 아니라 "그 답이 어느 조문에서 왔는지 사용자가 클릭해
확인할 수 있는가"로 정의한다.** 이 챗봇이 다루는 범위(코퍼스)에 없으면 지어내지 않고,
**범위 밖임을 말하는 것**이 정답이다.

> **"법령에 없다"가 아니라 "이 챗봇의 범위에 없다"** 다. 코퍼스는 식품 표시·광고 관련 법령
> 몇 건이고, 대한민국 법령 전체가 아니다(4절). 수출 라벨 요건이나 화장품 표시는 **다른 법령에
> 분명히 규정이 있다.** 거기에 "법령에 없습니다"라고 답하면 정당한 거절이 아니라 **틀린 답**이다.
> 이 구분이 이 제품에서 가장 틀리기 쉬운 지점이다.

> **법령명을 임의로 줄이지 않는다.** `표시광고법` 이라고만 쓰면 「**표시·광고의 공정화에 관한
> 법률**」(공정거래위원회 소관)과 구분되지 않는다. 둘 다 부당 표시·광고를 다루고 둘 다 그렇게
> 불린다. 이 제품은 **식품표시광고법** 처럼 구분 가능한 명칭을 쓴다 — 출처 칩이 검증 경로인데
> 라벨이 애매하면 오인의 근거가 된다.

**이 챗봇은 법률 자문이 아니다.** 조문을 찾아 보여 주는 안내이고, 개별 제품의 적법성 최종
판단은 하지 않는다. 이 경계를 화면에 상시 표시한다(5절) — 면피가 아니라 제품의 정직한 범위다.

## 2. 타겟 유저

**주 사용자** — 식품을 기획·제조해 **판매채널에 등록하는 사람.** 상세페이지 문구를 쓰다가
"이거 써도 되나" 에서 멈추고, 표시사항을 만들다가 "뭐가 빠졌나" 에서 멈춘다. 법령을 찾아
읽을 시간은 없고, 틀리면 되돌리는 비용이 크다.

**이 사용자의 특징이 설계에 미치는 영향:**

- 질문도 자료도 **한국어**다 → 코퍼스 언어 문제가 없다 (4절)
- 답을 그대로 믿을 수 없다 — **조문 원문을 확인해야 한다** → 출처 링크가 장식이 아니라 핵심 기능
- **모르면 모른다고 하는 편이 낫다.** 과징금·회수보다 "확인이 더 필요하다"가 싸다
- 질문에 **조문 번호가 그대로 들어온다** ("제8조 제1항 제3호가 뭔가요") → 검색이 정확한
  표기를 잡아야 한다 (PLAN 의 하이브리드 검색 근거)

**비사용자** — 수출 통관 담당자(다른 법령), 화장품·의약품 취급자(다른 법령),
법률 자문을 원하는 사람(이 제품의 경계 밖).

## 3. 핵심 기능 (MVP)

반드시 있어야 하는 최소 기능. 이 목록에 없는 것은 MVP가 아니다.

| # | 기능 | 사용자가 확인할 수 있는 것 |
|---|---|---|
| F1 | 질문 입력 → 답변 스트리밍 | 답이 토큰 단위로 나오고, **취소 버튼**으로 중단된다 |
| F2 | 근거 검색 | 답변에 쓰인 조문이 몇 개, 어떤 경로로 뽑혔는지 보인다 |
| F3 | 출처 공개 | 답변 아래 **출처 칩** → 누르면 **조문 원문과 law.go.kr 링크**가 열린다 |
| F4 | **근거 상태 3단** | 아래 표대로 화면이 달라진다 |
| F5 | 자동 판정 | **규칙 배지 + LLM 배지** 두 층으로 붙는다 |
| F6 | 사람 피드백 | 좋아요/싫어요를 남기고, **자동 판정 결과와 나란히** 볼 수 있다 |
| F7 | **엔진 선택** | API / 로컬 Ollama 를 화면에서 고르고, 현재 엔진과 연결 상태가 항상 보인다 |
| F8 | **시행일 표기 + 시행 예정 구분** | 근거 조문의 시행일이 보이고, **시행 예정 조문은 현행과 시각적으로 구분**된다 |

**F4·F5를 MVP에 넣는 이유** — 이 둘이 빠지면 "그럴듯한 답"과 "근거 있는 답"이 화면에서
구분되지 않는다. 그건 이 제품의 존재 이유 자체가 사라지는 것이다.

### F4 — 근거 상태

**3단으로는 부족하다.** 실제 질문 대부분이 코퍼스 안·밖에 걸친다 — 예: "SNS 협찬 광고도 이
법 적용을 받나요"는 **적용 여부는 코퍼스 안**, 협찬 대가관계 표시 의무는 공정위 소관이라
**코퍼스 밖**이다. 3단이면 답할 수 있는 절반까지 버리거나, "근거 약함"으로 뭉개서 어느 부분이
밖인지 사라진다. 둘 다 이 제품의 저울(1절)에서 나쁜 쪽이다.

| 상태 | 화면 | 뜻 |
|---|---|---|
| 근거 충분 | 답변 + 출처 칩 | 조문이 있고 답이 그 안에 있다 |
| 근거 약함 | 답변 + **한계 문장** + ⚠ 경고 배지 + 출처 칩 | 조문이 직접 말하지 않는 부분이 있다 |
| **일부 범위 밖** | 답변(코퍼스 안 부분) + **밖인 부분을 분리해 명시** | 질문이 경계에 걸쳤다 |
| 코퍼스 밖 (법령 질문) | 답변 없음 + 범위 안내 + **다른 법령 소관 안내** | 규정은 있으나 이 챗봇 밖 |
| **규범 밖 (법령 질문 아님)** | 답변 없음 + **이 챗봇의 목적 밖임만** 안내 | 다른 법령 언급을 붙이지 않는다 |

**마지막 두 줄을 나눈 이유** — "원가를 어떻게 낮추나"에 "다른 법령에 규정이 있을 수 있다"를
붙이면 **없는 규제를 시사하는 오답**이 된다.

**일부 범위 밖일 때, 코퍼스 안 부분과 밖 부분을 한 문단에 섞지 않는다.**

상태를 가르는 신호는 **검색 최고 점수의 두 임계값**, 그리고 규칙 하나 —
**답변이 조문 인용을 하나도 달지 않으면 "근거 충분"으로 표시하지 않는다.** 점수는 높은데
모델이 청크를 안 쓰는 경우가 흔하고, 임계값만으로는 못 잡는다.

> 임계값 수치는 여기 쓰지 않는다 — PLAN·구현 영역.

### F5 — 판정은 규칙과 LLM 두 층

| 판정 항목 | 방식 | 근거 |
|---|---|---|
| **인용 유효성** | **규칙** — 답변이 든 조문이 실제 검색된 청크 집합에 있는가 | 결정적·무료. 이 도메인에서 **가장 치명적인 실패가 조문 오인용**이다 |
| 거절 여부 | **규칙** — 답변을 생성하지 않고 범위 안내로 종료했는가 | 상태로 판정 가능 |
| 근거성 | **LLM** — 답변 문장이 제공된 조문에서 나왔는가 | 규칙으로 못 잰다 |

**규칙이 잡는 범위를 과장하지 않는다.** 인용 유효성 규칙이 보는 것은 **집합 소속**뿐이다.

| 잡는다 | 못 잡는다 |
|---|---|
| 검색된 청크에 없는 조문을 인용 | **번호는 맞고 내용을 왜곡** — 요건을 뒤집어 말해도 통과 |
| | **무관한 조문을 방패로 인용** — 집합에 있으면 통과 |

못 잡는 범위는 **LLM 근거성 + 사람 스팟체크**(9절)의 몫이다.

**전제 — 인용 표기에 법령명이 반드시 포함돼야 한다.** 법률·시행령·시행규칙에 각각 제8조가
있고, 한 법 안에서도 제8조·제8조의2, 제13조 계열 5개가 중복이다([FINDINGS](FINDINGS.md) 함정 ①).
법령명 없는 "제8조"는 규칙이 판정할 수 없다 — 이 전제가 없으면 규칙 자체가 성립하지 않는다.

- 명세가 "자동 판정(LLM-as-a-Judge, **기타 평가지표 등**)"이라고 써서 비-LLM 결정적 지표를
  허용한다. 규칙으로 잴 수 있는 것을 확률적 모델에 맡기지 않는다.
- **LLM 판정은 "현재 선택된 엔진"으로 돌린다.** 엔진마다 판정이 달라지는 것은 결함이 아니라
  확장 항목이 요구하는 **관측 대상**이다.
- **규칙 배지와 LLM 배지를 같은 모양으로 그리지 않는다** (5절 화면 규칙 4).

### 생성 엔진 — 둘 다 MVP

| | MVP | 확장 |
|---|---|---|
| 무엇 | **API + 로컬 Ollama 둘 다.** 화면에서 전환 | 둘을 **나란히 두고 답변 리듬·판정 결과를 비교** |
| 기본값 | **API** — Ollama 설치 없이 시작할 수 있는 쪽. 단 키 입력은 필요하다 (8절 A1†) | — |

명세는 "로컬 Ollama(`qwen3.5:2b` 등) **또는 API를** 활용해"라고 써서 **API를 1급 선택지로
허용**한다. 확장 점수가 붙는 것은 API를 쓰는 것이 아니라 **둘을 나란히 두고 비교하는 것**이다.

**자동 폴백을 넣지 않는다.** Ollama 실패 시 조용히 API로 넘어가면 사용자가 어느 엔진의 답을
보는지 알 수 없고, 확장 항목의 비교가 오염된다. 실패는 실패로 표시한다.

> **검색은 엔진 없이 동작한다.** 질의 임베딩이 브라우저에서 돌기 때문에, 키가 없는 방문자도
> **질문 → 조문 검색 → 출처 링크**까지 쓸 수 있다. 엔진이 필요한 것은 답변 생성과 LLM 판정뿐이다.
> 이 제품의 존재 이유가 "근거가 보이는가"이므로, 그 부분이 무설정으로 도는 것은 설계 의도다.

`https://www.law.go.kr/DRF/` . 실측 상세는 [FINDINGS](FINDINGS.md) 3·4절.

| 확인한 것 | 결과 |
|---|---|
| 조문 구조 | **조 → 항 → 호** 로 중첩되어 구조로 온다. 필드명은 [FINDINGS](FINDINGS.md) 3·4절 |
| 파싱 | **HTML 파싱이 필요 없다.** JSON/XML 로 구조화되어 온다 |
| 인용 URL | `law.go.kr/법령/<법령명>/제8조` → 200 확인. **조문 단위로 링크가 성립** |
| 시행일자 | 자료에 들어 있다 → "수집 시점"이 **"법령 시행일"** 이라는 더 정확한 형태가 된다 |

**대상 법령** (규모는 FINDINGS 4절):

- 식품 등의 표시·광고에 관한 법률 (37조) · 시행령 (18조) · 시행규칙 (22조)
- 고시「식품등의 **부당한 표시 또는 광고의 내용 기준**」 — 금지되는 표현의 구체 기준
- 고시「식품등의 **표시기준**」 — 의무 표시사항. 별표에 실제 방법이 있다
- 고시: 알레르기 유발식품 표시 / 영양성분·고카페인 / GMO 표시 / 자율심의 기준

> **코퍼스는 대한민국 법령의 부분집합이다.** 이 사실이 제품 문구를 규정한다 — 범위 밖 질문에
> "법령에 없습니다"라고 답하면 **틀린 답**이다. 예: 미국 수출 라벨 요건은 수입국 규정과
> 수출 관련 법령에 있고, 화장품 표시는 화장품법에 있다. 범위 밖 안내는 **"이 챗봇이 다루는
> 법령 범위 밖이며, 다른 법령에 규정이 있을 수 있다"** 까지 말해 주는 편이 정확하고 더 쓸모 있다.

> **그런데 "화장품법에 있습니다" 는 코퍼스에 근거가 없는 문장이다.** 코퍼스에 화장품법도 수출
> 관련 법령도 없으므로, 모델이 그 이름을 대면 위 원칙("코퍼스에 없으면 지어내지 않는다")을
> 정면으로 위반한다. 게다가 인용 유효성 규칙(3절 F5)은 **인용을 아예 달지 않은 문장**을 잡지
> 못한다 — 제품이 구조적으로 검증 못 하는 환각 경로가 된다.
>
> 그래서 경로를 둘로 나눈다:
>
> | 무엇 | 어떻게 |
> |---|---|
> | **코퍼스 밖임을 말하는 것** | 검색 결과로 판정 가능하므로 **모델 생성 허용** |
> | **다른 법령 이름을 대는 것** | **사람이 검수한 고정 안내 목록**에서만 꺼낸다. 목록에 없으면 "다른 법령 소관일 수 있다"까지만 |
>
> 고정 안내 목록(초안): 수출 라벨 요건 / 화장품 / 의약품 / 건강기능식품 기능성 표시 /
> 축산물 / 주류 / **표시·광고의 공정화에 관한 법률(공정위 소관)**.
> 이 목록의 문구는 생성 문장이 아니므로 **화면에서 구분 표시**하고, F5 인용 규칙의 예외로 둔다.

> **⚠ 시행 중인 판을 써야 한다.** API 의 `[현행]` 은 "지금 시행 중"을 뜻하지 않는다 —
> 「식품등의 표시기준」은 **시행 2028-01-01** 인 개정본이 `[현행]` 으로 온다
> ([FINDINGS](FINDINGS.md) 함정 ③). 청크마다 시행일을 기록하고 **오늘 기준으로 시행 중 /
> 시행 예정을 계산**해 화면에서 구분한다. **검색 결과의 시행일이 아니라 본문에서 읽는다.**

> **D2 확정 (S2)** — 법률 3종(식품표시광고법 제1~10조 · 시행령 제1~6조 · 시행규칙 제1~10조)
> + 고시 6종, **534 청크, 전부 시행 중.** 집행 조문(제재·과징금·벌칙·기구 등록)은 제외했다 —
> "이 문구 써도 되나"에 답하는 근거가 아니고, 넣으면 처벌 수준을 단정하게 된다.
> 시행 중인 판 취득 경로와 남은 한계는 [FINDINGS](FINDINGS.md) 함정 ③·④.

### 청크 규칙

- **한 청크에 하나의 중심 사실.** 단독으로 읽어도 주어와 맥락이 서야 한다
  → 이 자료에서는 **호(號)가 자연스러운 단위**다. 예: 제8조 제1항의 호 10개 = 금지 광고 유형 10가지
- 보존할 것: **식별자 · 본문 · 조문 인용 URL · 법령명과 조문 위치 · 시행일자 · 법령 종류**
  — **본문만 남기지 않는다.** 저장 구조는 구현 결정이므로 여기 쓰지 않는다
- **`조문가지번호` 를 식별자에 반영한다** — 제8조와 제8조의2가 구분되어야 한다 (FINDINGS 4절)
- **고시의 별표를 포함한다** — 빼면 "무엇을 어떻게 적어야 하는가"가 빠진다
- 조문을 요약해 옮기지 않는다. 법령 문장은 **원문 그대로**가 근거다 — 요약이 들어가면
  출처가 있어도 환각을 감추는 재료가 된다

## 5. 화면 구성

**단일 페이지.** 별도 라우팅 없이 한 화면에서 질문 → 근거 → 답변 → 판정이 모두 관찰된다.

```
┌───────────────────────────────────────────────┐
│ 헤더 — 무슨 법령을 근거로 답하는지              │
│   [엔진: API ▾ / Ollama]  ● 연결됨            │
│   📅 오늘(YYYY-MM-DD) 기준 시행 중 법령          │
│   ⚠ 법률 자문이 아닙니다 — 최종 확인은 식약처·전문가 │
├───────────────────────────────────────────────┤
│ 준비 상태 (첫 방문 다운로드가 있을 때만)        │
│   임베딩 모델 로딩 진행률 · 캐시 여부           │
├───────────────────────────────────────────────┤
│ 대화 영역                                      │
│   ⓘ 각 질문은 독립적으로 처리됩니다             │
│                                                │
│   [질문]                                       │
│   [검색 단계]  n개 조문 검색됨 · 방식           │
│   [답변]       스트리밍 · 취소 버튼             │
│   [⚠ 근거 약함] 있을 때만 + 한계 문장           │
│   [출처 칩] 식품표시광고법 제8조①3 → 클릭 시   │
│              (시행 예정이면 별도 표시)           │
│              근거 모달(조문 원문 + URL + 시행일) │
│                                                │
│   ┌ 규칙 판정 ─────────┐  결정적               │
│   │ 인용 유효 ✓  거절 ✗ │                      │
│   └────────────────────┘                      │
│   ┌ LLM 판정 (API) ────┐  확률적               │
│   │ 근거성 ✓  95/100   │                      │
│   └────────────────────┘                      │
│   [피드백]  👍 👎                              │
├───────────────────────────────────────────────┤
│ 입력창                                         │
└───────────────────────────────────────────────┘
```

**화면이 지켜야 할 규칙:**

1. **답변과 판정은 서로 다른 시각적 층에 둔다.** 생성 문장이 자연스럽다는 사실과 근거를
   가진 답이라는 사실은 다르므로, 한 덩어리로 보이면 안 된다
2. **출처 칩은 장식이 아니라 클릭 가능한 검증 경로다** — 누르면 조문 원문과 law.go.kr 링크가 나온다
3. **판정이 실패해도 답변과 나머지 UI는 유지된다** — 판정 실패 배지만 남긴다
4. **결정적 판정(인용·거절)과 확률적 판정(근거성)을 같은 모양으로 그리지 않는다**
5. **각 질문이 독립적으로 처리된다는 사실이 화면에 드러난다** (6절). 방법은 구현에서
6. **시행 예정 조문은 현행과 시각적으로 구분한다.** 자료가 그렇게 오기 때문에 화면에서
   구분하지 않으면 이 제품이 가장 하지 말아야 할 실수를 한다
7. **법령명을 임의로 줄이지 않는다** — 출처 칩은 구분 가능한 명칭을 쓴다 (1절)
8. **고정 안내 목록에서 온 문구는 생성 문장과 구분 표시한다** (4절)
9. **법률 자문이 아니라는 안내를 상시 표시한다.** 답변 아래가 아니라 헤더에 — 답을 읽기 전에
   보여야 한다
10. **모바일에서도 같은 정보가 보인다.** 처음부터 단일 컬럼으로 만든다 (D6 확정, PLAN)

## 6. 안 할 것 (비목표)

비목표는 사과가 아니라 **범위가 부풀지 않게 막는 장치**다.

- **법률 자문 · 개별 제품의 적법성 최종 판단** — 조문을 찾아 보여 주는 안내까지가 경계다
- **로그인·사용자 계정** — 피드백은 브라우저 로컬에만 남는다.
  → 따라서 **배포본에서 타인의 피드백은 수집되지 않고**, "피드백을 축적해 실패 사례를 모으는
  사이클"은 **내 브라우저 범위**에서만 성립한다. 이 한계를 확장 항목으로 부풀리지 않는다
- **서버·백엔드** — 정적 배포. 수집·임베딩은 빌드 시점에 끝낸다
- **법령 자동 동기화** — 코퍼스는 수동 갱신. 대신 **법령 시행일을 화면에 표기**한다 (F8)
- **코퍼스 밖 법령** — 수출 통관, 화장품·의약품 표시, **건강기능식품의 기능성 표시 허용 범위**,
  축산물·주류 개별 규정, **「표시·광고의 공정화에 관한 법률」(공정위 소관)** 등.
  다른 법령 소관이라는 **사실까지만** 안내하고, 그 문구는 고정 목록에서 꺼낸다 (4절)
- **대화 맥락 유지(멀티턴)** — 각 질문을 독립 처리한다. 근거 추적이 흐려지기 때문.
  → 단, **그 사실이 화면에 드러나야 한다** (5절 규칙 5). 안 하는 것과 숨기는 것은 다르다
- **다국어 UI** — 한국어 하나

## 7. 못 답할 때의 행동

F4의 3단 상태와 같은 축으로 읽는다.

| 상태 | 행동 |
|---|---|
| **근거 충분** | 조문 **요건을 인용하는 데까지** 답한다. **개별 제품의 해당 여부는 단정하지 않는다** — "제8조①3 에 해당할 수 있다" 이고 "쓰면 안 된다" 가 아니다 |
| **근거 약함** | 답하되 **조문이 직접 말하지 않는 부분을 명시**하고 경고 배지 |
| **일부 범위 밖** | 코퍼스 안 부분은 조문 근거로 답하고, **밖인 부분을 분리해 명시**한다. 두 부분을 한 문단에 섞지 않는다 |
| **코퍼스 밖 (법령 질문)** | 답하지 않고 범위 밖임을 안내 + **고정 목록에서** 다른 법령 소관을 안내 (4절) |
| **규범 밖 (법령 질문 아님)** | 이 챗봇의 **목적 밖임만** 안내한다. **다른 법령 언급을 붙이지 않는다** — 없는 규제를 시사하게 된다 |

| 그 밖의 상황 | 행동 |
|---|---|
| 엔진 연결 실패 | 답변 상태와 **분리해서** 표시. **자동 폴백을 하지 않는다** |
| 판정 실패 | 판정 배지 자리에 실패 표시. **답변은 그대로 둔다** |

> **"근거 충분" 행이 왜 필요한가** — 이 코퍼스의 조문 요건이 평가적이다. 제8조①1 은
> "질병의 예방·치료에 효능이 있는 것으로 **인식할 우려가 있는** 표시 또는 광고"다. 조문이 잘
> 검색돼도 *이 문구가 그 요건에 해당하는가* 는 판단이고, 그 판단이 틀려도 인용 유효성 규칙은
> 통과한다(3절 F5). 근거가 가장 충분할 때 화면이 가장 단정적으로 읽히는 것을 막아야 한다.
> 헤더의 상시 배너는 개별 답변의 단정을 상쇄하지 못한다.

> **정당한 거절은 실패가 아니다.** 근거 없는 걸 지어내지 않은 것이므로 경계가 작동한
> 증거로 센다. 이 도메인에서는 특히 그렇다 — 틀린 확답의 대가가 과징금이다.

## 8. 수용 기준 (배포 전·후 통과할 문)

명세는 "배포 **후** 수용 기준을 정하고, 그 기준으로 동작을 다시 확인"하라고 한다. 그래서
**통과선 수치는 배포 후에 정하되, 지금 쓸 수 있는 실패 조건은 지금 못 박는다.**

### 수용 기준 전용 질문 3개

평가 세트 9개(9절)를 게이트로 쓰지 않는다. **그 9개에 맞춰 튜닝한 뒤 그 9개로 게이트를
통과하면 과적합이다.** 아래 3개는 **실험에 쓰지 않는다.**

| | 유형 | 용도 |
|---|---|---|
| G1 | 정상 (코퍼스 안) | 출처 칩·조문 링크 확인 |
| G2 | 경계 (근거 약함) | 경고 배지 재현 |
| G3 | 범위 밖 (다른 법령) | 지어내지 않고 범위를 안내하는지 확인 |

> `[결정 필요]` **D8** G1~G3의 실제 문장. 코퍼스 확정 후 정한다 (D2에 종속).

### 확인 항목

배포한 URL에서 **직접 실행해** 하나씩 확인한다.

| # | 기준 | 확인 방법 |
|---|---|---|
| A1 | 링크만 받은 사람이 페이지를 열고, 화면 안내대로 최소 준비를 마쳐 질문할 수 있다 † | 다른 브라우저 프로필에서 접속 |
| A2 | **G1** 에서 출처 칩이 뜨고 **law.go.kr 조문으로 이동한다** | 클릭해서 조문 확인 |
| A3 | **G3** 에서 **코퍼스에 없는 내용을 지어내지 않는다** | 범위 안내 문구에 코퍼스 밖 법령의 **내용**이 들어갔는지 확인. 법령 소관 안내는 **고정 목록**에서 온 것이어야 한다 |
| A4 | **G2** 에서 경고 배지가 실제로 뜬다 — **최종 확정 세팅에서** ‡ | 재현 |
| A5 | 모든 **응답**(답변 또는 범위 안내)에 **판정 배지가 붙는다** (실패 시 실패 표시) | G1~G3 전부 |
| A6 | 피드백을 남기면 **판정 결과와 함께 보인다** | 👍/👎 후 화면 확인 |
| A7 | 스트리밍 중 **취소가 동작한다** | 취소 버튼 클릭 |
| A8 | 첫 방문에서 다운로드가 있으면 **진행률이 보인다** | 캐시 지우고 재접속 |
| A9 | **화면에서 엔진을 전환할 수 있고, 현재 엔진이 항상 보인다** | API ↔ Ollama 왕복 |
| A10 | 근거 조문의 **시행일이 보이고, 시행 예정이 현행과 구분된다** | 헤더/근거 모달 확인 |
| A11 | **법률 자문이 아니라는 안내가 답을 읽기 전에 보인다** | 헤더 확인 |

‡ **A4 주의** — 근거 약함을 가르는 신호는 임계값이고, 그 임계값이 **실험 축 2번**(9절)이다.
질문을 실험에 쓰지 않아도 **G2 의 판정 결과는 실험 축을 따라 움직인다.** 임계값을 바꾸면 A4 를
**반드시 재확인한다.** 또는 G2 를 임계값과 무관한 신호(인용을 하나도 달지 않는 경우)로 재현되게
고르면 실험 축에서 독립한다.

† **A1의 정직한 범위** — 정적 배포에 API 키를 넣을 수 없으므로(6절 비목표: 서버 없음),
방문자가 자기 키를 입력해야 할 수 있다. 완전한 무설정 접속은 서버가 있어야 가능하고 그건
비목표다. 따라서 A1이 보장하는 것은 **"Ollama 설치보다 훨씬 가벼운 준비"** 이며, 명세는 이
수준을 허용한다. **단, 조문 검색과 출처 확인은 키 없이도 동작한다** (3절).

### 실패 조건 (측정 없이 지금 확정)

측정하고 나서 넘을 수 있는 선을 그으면 게이트가 아니다. 다음은 수치와 무관하게 배포 실패다:

- **범위 밖 질문에서 지어낸 답이 하나라도 나오면 배포 실패로 본다**
- **검색된 청크에 없는 조문을 인용하면 배포 실패로 본다**
  (F5 규칙이 실제로 잴 수 있는 범위로 좁혔다. 내용 왜곡·무관 인용은 규칙이 못 잡으므로
  LLM 근거성과 사람 스팟체크의 몫이다 — 3절)
- **출처 칩의 링크가 실제 조문으로 가지 않으면 배포 실패로 본다**
- **시행 예정 조문을 현행 기준으로 제시하면 배포 실패로 본다** ([FINDINGS](FINDINGS.md) 함정 ③)
- **대한민국 법령 전체에 규정이 없다는 뜻으로 읽히는 답변이 하나라도 있으면 배포 실패로 본다**

마지막 조건은 **표현이 아니라 의미** 기준이다. 세 경우를 구분한다:

| 답변의 뜻 | 판정 |
|---|---|
| "이 챗봇이 다루는 법령 범위에 없다" | **정당** |
| "이 법령에는 해당 규정이 없다" (코퍼스에 든 법을 실제로 확인한 경우) | **정당** |
| "대한민국 법령에 그런 규정은 없다" | **배포 실패** |

> `[결정 필요]` **D3** A2·A3의 통과선 **수치**. 배포 후 측정하고 정한다 (명세가 그렇게 요구).

## 9. 평가 세트 · 루브릭 (수용 기준과 다른 물건)

수용 기준은 **나가기 전 통과할 문**, 루브릭은 **통과한 뒤 세팅을 비교할 자**.

**아래 9개는 루브릭 전용이며 수용 기준(8절)에 쓰지 않는다.** 실험 도중 바꾸지 않는다.
아래는 **초안** — 코퍼스 확정 후 근거가 실제로 있는지 확인해 확정한다.
**실제로 판매채널에서 부딪힌 문구를 쓴다.**

| | 유형 | 질문 초안 | 기대 행동 |
|---|---|---|---|
| Q1 | 정상 | 일반식품 상세페이지에 "면역력 강화"라고 써도 되나요? | 근거 조문 + 출처 |
| Q2 | 정상 | 알레르기 유발물질은 어떻게 표시해야 하나요? | 근거 조문 + 출처 |
| Q3 | 정상 | 영양성분 표시는 어떤 제품에 의무인가요? | 근거 조문 + 출처 |
| Q4 | 경계 | "무첨가"라고 강조해서 표시해도 되나요? | 조건이 붙는다는 것까지, 단정 없이 |
| Q5 | **일부 범위 밖** | SNS 협찬 광고도 이 법 적용을 받나요? | **적용 여부는 조문 근거로**, 협찬 대가관계 표시(공정위 소관)는 **분리해 명시** |
| Q6 | 경계 | 자율심의를 받아야 하는 광고는 어디까지인가요? | 코퍼스 범위만, 한계 명시 |
| Q7 | **코퍼스 밖** | 미국으로 수출할 때 라벨 요건이 뭔가요? | **범위 밖 안내** + 고정 목록에서 수출 소관 안내. (S2 확인: 코퍼스에 수출 라벨 요건 근거가 없다) |
| Q8 | **코퍼스 밖** | 화장품에 "주름 개선"이라고 써도 되나요? | **범위 밖 안내** + 고정 목록에서 화장품 소관 안내. **내용을 대지 않는다** |
| Q9 | **규범 밖** | 이 제품 원가를 어떻게 낮출까요? | **목적 밖임만** 안내. 다른 법령 언급을 붙이지 않는다 |

> **Q8 과 Q9 는 다른 종류의 실패를 잡는다.** Q8 에 "법령에 없습니다"라고 답하면 정당한 거절이
> 아니라 틀린 답이다 — 규정은 분명히 있고 코퍼스에 없을 뿐이다. 반대로 Q9(원가)에 "다른 법령에
> 규정이 있을 수 있다"를 붙이면 **없는 규제를 시사하는 오답**이다.
>
> **Q2·Q3 는 근거가 코퍼스에 실제로 있는지 아직 확인되지 않았다.** Q2(알레르기)의 후보 고시는
> 「**어린이 기호식품** 등의 알레르기 유발 식품 표시기준」으로 **대상이 한정**돼 있고, 일반
> 식품 쪽 근거는 「표시기준」 별표일 텐데 그 고시는 시행 2028-01-01 이다([FINDINGS](FINDINGS.md) 함정 ③).
> → **S2 에서 Q1~Q9 각각의 근거 조문을 코퍼스에서 지목할 수 있는지 확인하고, 못 찾은 Q 는
> 그 자리에서 유형을 바꾼다.** 실험 단계까지 미루지 않는다.

### 루브릭 지표

| 지표 | 측정 | 판정 출처 | 관측값 | 비교 기준선 |
|---|---|---|---|---|
| 조문 인용 유효율 | Q1~Q6 중 인용 조문이 실제 검색된 청크에 있는 답 수 | **규칙** | `[미측정]` | `[최초 측정값을 기준선으로]` |
| 일부 범위 밖 분리 | Q5 에서 안·밖 부분을 분리해 말한 수 | **사람** | `[미측정]` | `[최초 측정값을 기준선으로]` |
| 코퍼스 밖 처리 | Q7·Q8 에서 범위 밖 + 고정 목록 안내를 한 수 | **규칙 + 사람** | `[미측정]` | `[최초 측정값을 기준선으로]` |
| 규범 밖 거절 | Q9 에서 다른 법령 언급 없이 목적 밖만 안내한 수 | **규칙** | `[미측정]` | `[최초 측정값을 기준선으로]` |
| 근거성 | Q1~Q9 중 근거성 통과 비율 | **LLM** | `[미측정]` | `[최초 측정값을 기준선으로]` |
| 불필요한 거절 | Q1~Q6 중 통째로 거절한 수 (낮을수록 좋음) | **규칙** | `[미측정]` | `[최초 측정값을 기준선으로]` |
| **단정 회피** | Q1·Q4 에서 개별 제품 해당 여부를 단정하지 않은 수 | **사람** | `[미측정]` | `[최초 측정값을 기준선으로]` |

> "목표값"이라 부르지 않는다. 측정 후에 채우는 값을 목표라 부르면 8절과 같은 함정에 빠진다.
> **최초 측정을 기준선으로 삼고, 세팅을 바꿀 때마다 그 기준선과 비교한다.**

### 판정 신뢰도 스팟체크

**판정으로 시스템을 재는 이상, 판정 자체가 검증되지 않으면 표의 숫자가 근거를 잃는다.**
평가 세트 중 **3개를 사람이 직접 채점**해 LLM 판정과 대조하고 불일치를 기록한다.

> [FINDINGS](FINDINGS.md) 2절에서 확인된 것: 2b 모델은 정답 케이스의 형식은 지키지만,
> **오답·환각을 실제로 잡아내는지는 아직 확인되지 않았다.** 스팟체크가 그걸 메운다.

### 실험 축 — 3개로 축소, 한 번에 하나만

9질문 × 8축 = 72회 실행 + 판정까지 144회 LLM 호출은 로컬 2b로 하루가 사라진다. 축을 줄이고
하나를 확실히 판다.

1. **top-k** (근거 조문 개수)
2. **약한 근거 임계값**
3. **프롬프트의 인용 규칙 문구**

시간이 남으면 나머지.

### 실패 분석

실패한 답(틀린 답 · 근거 없는 답 · 불필요한 거절)마다 **어느 단계가 원인인지** 기록한다:
청크 분할 / 임베딩·검색 / 프롬프트 / 생성 / 판정.

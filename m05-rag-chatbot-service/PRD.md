# PRD — Claude Code 문서 안내 챗봇

> Main Quest 3 제출용. 요구 항목은 [README](README.md), 구현 전 실측은 [FINDINGS](FINDINGS.md) 참고.
> 작성 2026-08-28 / 상태: 초안 (사람 검토 전)
>
> **`[결정 필요]`** 는 판단 근거가 아직 없어 비워 둔 칸이다. 임의로 채우지 않는다.

---

## 1. 문제 정의

**이 챗봇이 어떤 질문에, 어떤 근거로 답해 주는가**

Claude Code 설정·확장 기능(CLAUDE.md, settings.json, hooks, MCP, skills, subagents,
slash commands)에 대한 "이거 어떻게 설정해요?" 류의 질문에, **공식 문서 원문과 그 URL을
근거로** 답한다.

**왜 RAG여야 하는가** — 이 도메인은 일반 LLM이 특히 잘 틀린다:

| 실패 양상 | 예 |
|---|---|
| 없는 설정 키를 지어냄 | 그럴듯한 이름의 `settings.json` 키를 만들어 낸다 |
| 옛 스펙을 현재로 말함 | 도구가 빠르게 바뀌어 학습 시점의 스펙이 이미 다르다 |
| 파일 위치를 혼동 | 프로젝트 `.claude/` vs `~/.claude/` vs 로컬 오버라이드 |
| 비슷한 기능을 뒤섞음 | hooks / skills / subagents / MCP 의 경계 |

**그래서 이 챗봇의 성공은 "답이 자연스러운가"가 아니라 "그 문장이 실제 문서 어느 줄에서
왔는지 사용자가 클릭해서 확인할 수 있는가"로 정의한다.** 문서에 없으면 지어내지 않고
없다고 말하는 것이 정답이다.

## 2. 타겟 유저

**주 사용자** — Claude Code를 쓰기 시작했고, 설정을 바꾸려는데 *어느 파일의 어느 키*인지
모르는 개발자. 공식 문서가 191페이지라 어디를 봐야 할지부터 막힌다.

**이 사용자의 특징이 설계에 미치는 영향:**

- 질문은 **한국어**로 하지만 문서 원문은 한/영이 섞여 있다 (아래 5절)
- 답을 그대로 믿지 않고 **원문을 확인하려 한다** → 출처 링크가 장식이 아니라 핵심 기능
- 틀린 설정을 넣으면 도구가 조용히 동작을 안 하므로, **모르면 모른다고 하는 편이 낫다**
  → 불필요한 거절보다 **근거 없는 확답이 더 큰 손해**

**비사용자** — Claude Code를 처음 듣는 사람(개념 소개는 공식 문서가 이미 잘 한다),
Anthropic API 일반 사용자(도메인 밖).

## 3. 핵심 기능 (MVP)

반드시 있어야 하는 최소 기능. 이 목록에 없는 것은 MVP가 아니다.

| # | 기능 | 사용자가 확인할 수 있는 것 |
|---|---|---|
| F1 | 질문 입력 → 답변 스트리밍 | 답이 토큰 단위로 나오고, **취소 버튼**으로 중단된다 |
| F2 | 근거 검색 | 답변에 쓰인 청크가 몇 개, 어떤 경로로 뽑혔는지 보인다 |
| F3 | 출처 공개 | 답변 아래 **출처 칩** → 누르면 원문 조각과 **문서 URL**이 열린다 |
| F4 | 약한 근거 규칙 | 근거가 약하면 단정하지 않고 **자료의 한계를 말하고**, 화면에 경고 배지가 뜬다 |
| F5 | 자동 판정 | 답변 옆에 **판정 배지** — 근거성·환각 없음·인용 여부·정당한 거절 |
| F6 | 사람 피드백 | 좋아요/싫어요를 남기고, **자동 판정 결과와 나란히** 볼 수 있다 |

**F4·F5를 MVP에 넣는 이유** — 이 둘이 빠지면 "그럴듯한 답"과 "근거 있는 답"이 화면에서
구분되지 않는다. 그건 이 제품의 존재 이유 자체가 사라지는 것이다.

### 생성 엔진

| | MVP | 확장 |
|---|---|---|
| 경로 | 로컬 Ollama (무료, 명세의 기본 경로) | API 엔진 선택 추가 |
| 이유 | 비용 0, 명세가 기본으로 제시 | **채점자가 링크만으로 써 볼 수 있게** + 평가 5번 "확장 시도" |

> 명세는 로컬 Ollama를 쓰면 "실행 안내와 `OLLAMA_ORIGINS` 설정법을 README에 정리"하라고
> 허용하지만, 그 경우 링크를 받은 사람이 Ollama를 깔아야 동작한다. API 엔진을 나란히 두면
> 제출 요건("다른 사람이 링크만으로 사용")과 평가 5번을 같이 만족한다.
>
> `[결정 필요]` API 엔진을 무엇으로 할지 — 키를 사용자가 화면에서 입력하는 방식이면
> 배포본에 키를 넣지 않아도 된다. 확장 슬라이스에서 정한다.

## 4. 근거 자료 계획

### 출처

**Claude Code 공식 문서** — `https://code.claude.com/docs/`

수집 경로를 실제로 확인했다 (2026-08-28):

| 확인한 것 | 결과 |
|---|---|
| 기계 판독 색인 | `https://code.claude.com/docs/llms.txt` → **191개 영문 페이지** 목록 |
| 원문 형식 | 각 페이지 URL 뒤에 **`.md`** 를 붙이면 깨끗한 마크다운 (HTML 파싱 불필요) |
| 한국어 원문 | `docs/ko/<slug>.md` 로 **대부분 존재**. 단 일부는 영문만 (`slash-commands` 404 확인) |
| 인용용 URL | `.md` 를 뗀 주소가 사람이 읽는 문서 페이지 — 그대로 출처 링크로 쓴다 |

### 범위 — 191페이지 전부가 아니다

**"설정과 확장"** 한 주제로 좁힌다. 이 사용자가 실제로 막히는 곳이고, 오답을 판별하기 쉬워
루브릭이 성립한다.

수집 대상 후보:
`memory`(CLAUDE.md) · `settings` · `hooks` · `mcp` · `skills` · `sub-agents` ·
`slash-commands` · `claude-directory` · `features-overview`(언제 무엇을 쓰나)

> `[결정 필요]` 최종 페이지 목록과 청크 수. 자료 수집 슬라이스에서 원문을 읽고 확정한다.
> 커리큘럼 실습 기준은 8~15청크이나 명세는 수를 강제하지 않는다.

### 청크 규칙

- **한 청크에 하나의 중심 사실.** 단독으로 읽어도 주어와 맥락이 서야 한다
- 필드: `id` · `text` · `url` · `section` · `vector` — **본문만 남기지 않는다**
- ID 규칙: `CC-001` 부터 (`CC` = Claude Code)
- 원문에 없는 연결을 요약으로 덧붙이지 않는다 — 출처가 있어도 환각을 감추는 재료가 된다

### 한국어 / 영어 결정

`[결정 필요]` 코퍼스를 **한국어 원문 기준**으로 할지, **영문 기준**으로 할지.

- 한국어 기준: 한국어 질문과 같은 언어라 검색이 유리. 단 일부 페이지가 없어 구멍이 생긴다
- 영문 기준: 전 페이지 커버. 단 한국어 질문 ↔ 영문 청크의 **교차언어 검색**이 변수가 된다

> 이 선택 자체가 **실험 축으로 쓸 만하다** (평가 4번의 성능 비교표 재료). 자료 수집
> 슬라이스에서 양쪽을 만들어 비교할지, 하나만 고를지 결정한다.

## 5. 화면 구성

**단일 페이지.** 별도 라우팅 없이 한 화면에서 질문 → 근거 → 답변 → 판정이 모두 관찰된다.

```
┌─────────────────────────────────────────┐
│ 헤더 — 이 챗봇이 무엇을 근거로 답하는지  │
│        + 엔진/모델 상태 (연결됨/안 됨)   │
├─────────────────────────────────────────┤
│ 준비 상태                                │
│   임베딩 모델 로딩 진행률 · 캐시 여부     │
│   (첫 방문 다운로드가 있을 때만)          │
├─────────────────────────────────────────┤
│ 대화 영역                                │
│   [질문]                                 │
│   [검색 단계]  n개 청크 검색됨 · 방식     │
│   [답변]       스트리밍 · 취소 버튼       │
│   [⚠ 약한 근거] 있을 때만                │
│   [출처 칩] CC-003  CC-007  → 클릭 시    │
│              근거 모달(원문 조각 + URL)   │
│   [판정 배지] 근거성 · 인용 · 거절 · 점수 │
│   [피드백]    👍 👎                      │
├─────────────────────────────────────────┤
│ 입력창                                   │
└─────────────────────────────────────────┘
```

**화면이 지켜야 할 규칙:**

1. **답변과 판정은 서로 다른 시각적 층에 둔다.** 생성 문장이 자연스럽다는 사실과 출처를
   가진 답이라는 사실은 다르므로, 한 덩어리로 보이면 안 된다
2. **출처 칩은 답변 뒤에 붙는 장식이 아니라 클릭 가능한 검증 경로다** — 누르면 실제
   원문 조각과 문서 URL이 나온다
3. **판정이 실패해도 답변과 나머지 UI는 유지된다** — 판정 실패 배지만 남긴다
4. `[결정 필요]` 모바일 반응형 — 명세의 "완성도" 항목. 확장으로 뺄지 MVP에 넣을지

## 6. 안 할 것 (비목표)

비목표는 사과가 아니라 **범위가 부풀지 않게 막는 장치**다.

- **로그인·사용자 계정** — 피드백은 브라우저 로컬에만 남는다
- **서버·백엔드** — 정적 배포. 수집·임베딩은 빌드 시점에 끝낸다
- **문서 자동 동기화** — 코퍼스는 수동 갱신. 문서가 바뀌어도 자동으로 따라가지 않는다
- **Claude Code 문서 밖의 질문** — Anthropic API 일반, 다른 AI 도구, 코드 디버깅
- **대화 맥락 유지(멀티턴)** — 각 질문을 독립적으로 처리한다. 근거 추적이 흐려지기 때문
- **다국어 UI** — 한국어 하나

## 7. 못 답할 때의 행동

| 상황 | 행동 |
|---|---|
| 검색은 됐지만 근거가 약함 | 답하되 **자료의 한계를 명시**하고 화면에 경고 배지. 단정하지 않는다 |
| 도메인 밖 질문 | 답하지 않고 **이 챗봇이 다루는 범위를 안내**한다 |
| 엔진 연결 실패 | 답변 상태와 **분리해서** 표시 — 답이 나쁜 것과 엔진이 없는 것은 다른 문제다 |
| 판정 실패 | 판정 배지 자리에 실패 표시. **답변은 그대로 둔다** |

> **정당한 거절은 실패가 아니다.** 근거 없는 걸 지어내지 않은 것이므로 경계가 작동한
> 증거로 센다. 루브릭에서도 그렇게 센다.

## 8. 수용 기준 (배포 전 통과할 문)

배포한 URL에서 **직접 실행해** 하나씩 확인한다. 하나라도 실패하면 배포된 것이 아니다.

| # | 기준 | 확인 방법 |
|---|---|---|
| A1 | 링크만 받은 사람이 페이지를 열고 질문할 수 있다 | 다른 브라우저 프로필에서 접속 |
| A2 | 정상 질문 3개 모두 **출처 칩이 뜨고 URL이 열린다** | 클릭해서 실제 문서로 이동 확인 |
| A3 | 무근거 질문 3개 모두 **지어내지 않는다** | 답변에 문서에 없는 사실이 없음 |
| A4 | 약한 근거일 때 **경고 배지가 실제로 뜬다** | 경계 질문으로 재현 |
| A5 | 모든 답변에 **판정 배지가 붙는다** (실패 시 실패 표시) | 9개 질문 전부 |
| A6 | 피드백을 남기면 **판정 결과와 함께 보인다** | 👍/👎 후 화면 확인 |
| A7 | 스트리밍 중 **취소가 동작한다** | 취소 버튼 클릭 |
| A8 | 첫 방문에서 다운로드가 있으면 **진행률이 보인다** | 캐시 지우고 재접속 |

> `[결정 필요]` A2·A3의 통과선. 명세 예시는 "대표 질문 N개 중 근거 있는 답변 M개 이상".
> 3/3을 요구할지 2/3으로 둘지는 **실험 전 측정값을 보고** 정한다.

## 9. 평가 세트 (루브릭용 — 수용 기준과 다른 물건)

수용 기준은 **나가기 전 통과할 문**, 루브릭은 **통과한 뒤 세팅을 비교할 자**.

질문 9개를 고정하고 실험 도중 바꾸지 않는다. 아래는 **초안** — 코퍼스 확정 후 문서에
근거가 실제로 있는지 확인해 확정한다.

| | 유형 | 질문 초안 | 기대 행동 |
|---|---|---|---|
| Q1 | 정상 | hook은 어떤 파일에 설정하나요? | 근거 있는 답 + 출처 |
| Q2 | 정상 | subagent와 skill은 언제 각각 쓰나요? | 근거 있는 답 + 출처 |
| Q3 | 정상 | 프로젝트 설정과 전역 설정이 충돌하면 어느 쪽이 이기나요? | 근거 있는 답 + 출처 |
| Q4 | 경계 | MCP 서버가 연결이 안 되는데 왜 그런가요? | 문서에 있는 범위만, 한계 명시 |
| Q5 | 경계 | CLAUDE.md를 세션 중간에 고치면 바로 반영되나요? | 근거 범위 안에서만 |
| Q6 | 경계 | hook으로 커밋을 막을 수 있나요? | 단정 대신 문서가 말하는 선까지 |
| Q7 | 무근거 | Claude Code 요금제가 어떻게 되나요? | **정당한 거절** |
| Q8 | 무근거 | 파이썬 리스트 정렬하는 법 알려줘 | **정당한 거절** |
| Q9 | 무근거 | 다음 버전에 어떤 기능이 나오나요? | **정당한 거절** |

### 루브릭 지표

| 지표 | 측정 | 목표값 | 실험 전 |
|---|---|---|---|
| 출처 인용률 | Q1~Q6 중 `cited:true` 수 | `[실험 전 측정 후 결정]` | `[미측정]` |
| 정당한 거절률 | Q7~Q9 중 `refusal:true` 수 | `[실험 전 측정 후 결정]` | `[미측정]` |
| 근거성 | Q1~Q9 중 `grounded:true` 비율 | `[실험 전 측정 후 결정]` | `[미측정]` |
| 불필요한 거절 | Q1~Q6 중 거절한 수 (낮을수록 좋음) | `[실험 전 측정 후 결정]` | `[미측정]` |

### 실험 축 — 한 번에 하나만 바꾼다

- **검색 축**: top-k / 약한 근거 임계값 / 벡터·키워드 구성 / **코퍼스 언어(한↔영)**
- **프롬프트 축**: 근거 원칙 문구 / 길이 지시 / `[ID]` 인용 규칙 / 도메인 밖 거절 문구

### 실패 분석

실패한 답(틀린 답 · 근거 없는 답 · 불필요한 거절)마다 **어느 단계가 원인인지** 기록한다:

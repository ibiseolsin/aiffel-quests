### 청크 ID 충돌 점검 (S3 완료 기준)

ID 규칙을 정한 뒤 전수 검사했다. 규칙이 `{doc}-p{page}` 이므로 **같은 페이지에서 나온 청크는
서로 같은 ID 를 갖는다.** 당시에는 이것을 충돌로 보지 않았다 — 페이지 단위로 묶어 보여 주면
사람이 읽을 때 충분하다고 판단했기 때문이다 (D2 참고).

| 검사 | 결과 |
|---|---|
| 서로 다른 문서 사이 ID 중복 | 0 |
| 같은 문서 안 서로 다른 페이지 ID 중복 | 0 |
| 같은 문서 같은 페이지 ID 중복 | 189건 (규칙상 정상으로 판정) |

> 이 189건이 4단계에서 문제로 돌아왔다. 근거 모달이 청크 하나를 가리켜야 하는데
> ID 가 페이지까지만 있어 어느 청크인지 정하지 못했다.

### 출력 형식 결정 근거 (S9)

받는 쪽이 파일을 한 번에 읽는 구조였고, 행 수가 527 뿐이라 한 덩어리가 단순했다.
**D5 를 정할 때 스트리밍을 고려하지 않았다** — 그때는 스트리밍이 범위에 없었다.

| 검토한 형식 | 채택 | 이유 |
|---|---|---|
| JSON 배열 하나 | 채택 | `json.loads` 한 번으로 끝난다 |
| NDJSON | 보류 | 받는 쪽이 줄마다 파싱해야 해 당시엔 이득이 없었다 |
| CSV | 기각 | 중첩 메타를 담지 못한다 |

> 4단계에서 스트리밍이 범위에 들어와 이 판단이 뒤집혔다 (D8).

### 엔진 설정 결정 근거 (S13)

로컬 엔진 하나만 붙였고, 변수 이름이 무엇을 가리키는지 바로 보이는 편이 낫다고 봤다.
기본값을 두지 않은 판단은 4단계에서도 유지된다 — **바뀐 것은 변수 이름뿐이다.**

| 검토 항목 | 당시 결정 |
|---|---|
| 변수 이름 | `OLLAMA_URL` (D4) |
| 기본값 | 두지 않는다 — 엉뚱한 데로 조용히 붙는 것을 막는다 |
| 없을 때 동작 | 즉시 오류 |
| 폴백 | 없음 |

### 자동화로 못 잰 것 (1~3단계)

- **표가 깨진 3건의 실제 손실량** — 원본 PDF 의 표 셀 수를 세지 않았다
- **청크 크기 900자의 적정성** — 600/900/1200 을 비교하지 않았다
- **한국어 토큰화 품질** — 형태소 분석기와 대조하지 않았다
- **프롬프트의 「없으면 없다고 답하라」 효과** — 줄어든 것 같지만 수치가 없다

### 검증 원칙 (1단계에서 정해 계속 쓴다)

1. 「된다」는 실행해서 확인한 것만 쓴다
2. 확인하지 못한 것은 「미확인」으로 남기고, 되는 것처럼 요약하지 않는다
3. 완료 기준 일부를 확인하지 못했으면 슬라이스를 체크하지 않는다
4. 단일 실행으로 잰 차이를 효과라고 쓰지 않는다

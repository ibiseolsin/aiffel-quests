## 1. 불편 장면

**과업**: `aiffel-quests/m05-rag-chatbot-service` 의 슬라이스 구현. 슬라이스 S0~S13 을
세션 하나에 하나씩 맡겼다.

**입력**: 매 세션 고정 프롬프트 —
「`PRD.md`, `PLAN.md` 읽고 슬라이스 N 진행. 끝나면 `PLAN.md` 체크하고 커밋.」

**무엇이 잘못됐나**: 후반 슬라이스로 갈수록 세션이 **이미 폐기된 결정을 현재 규칙으로 읽었다.**
가장 뚜렷한 사례는 로컬 Ollama 동작 여부다. 초기 세션이 「배포본에서 로컬 Ollama 는 안 된다」로
결론 내려 그것을 `FINDINGS.md` 9절과 화면 문구 3곳에 남겼는데, 나중에 실제로 확인해 보니
**「된다」가 답이었다.** 2026-08-30 커밋 `m05: 배포본에서 로컬 Ollama 가 된다 — FINDINGS 9절
결론을 뒤집고 틀린 화면 문구를 고침` 이 그 되돌림이다. 그 사이 세션들은 문서에 남은 옛 결론을
그대로 읽고 화면 문구를 만들었다.

**내가 스스로 만든 대응책이 증거다**: `m05-rag-chatbot-service/PLAN.md:464` 에
「**다음 세션이 잘못 판단하기 쉬운 것 셋**」이라는 절을 손으로 추가해야 했다. 문서가
후속 세션을 오판하게 만든다는 것을 알고 있었고, 문서 안에 경고를 더 넣는 방식으로 막으려 했다.

**규모**: 그 시점 `PLAN.md` 는 **58,097 바이트 / 581줄**이고 한 번도 접힌 적이 없다.
`PRD.md` 35,564 바이트를 더하면 세션이 매번 **93KB** 를 읽고 시작했다. 그중 현재 슬라이스에
해당하는 부분은 수십 줄이다.

## 2. 이 불편이 정말 하네스 기능에서 온 것인가

먼저 의심해야 할 다른 원인들:

| 후보 원인 | 배제·유보 판단 |
|---|---|
| **모델 선택** | 배제 못 함. m05 는 여러 모델 등급이 섞여 돌았다 → 실험에서 **모델을 고정**해 분리한다 |
| **과업 난이도** | 배제 못 함. 후반 슬라이스가 더 어려웠다 → 실험에서 **난이도가 같은 fixture** 를 쓴다 |
| **저장소 상태** | 관련 있음. 코드가 커질수록 읽을 것이 늘었다 → fixture 는 코드를 **3줄 스텁 하나**로 고정한다 |
| **네트워크** | 무관해 보인다. 되돌림은 지연이 아니라 **내용 오류**였다 |
| **내 요청 문장** | **배제 못 한다.** 고정 프롬프트가 「`PLAN.md` 읽고」라고만 했지 「완료 절은 건너뛰라」고 하지 않았다. 이건 하네스가 아니라 **내 지시문의 문제일 수 있다** |
| **문서 자체의 오류** | 관련 있음. 옛 결론이 틀렸던 것이지 문서가 길어서가 아닐 수 있다 |

마지막 둘이 이 실험이 진짜로 다투는 대안 설명이다. 이 실험은 **지시문과 문서 내용을 고정한 채
완료 절 본문의 유무만** 바꿔, 남는 차이가 있는지 본다. 차이가 없다면 원인은 하네스의 컨텍스트
관리가 아니라 지시문이나 문서 내용 쪽에 있다는 뜻이고, 나는 그렇게 적을 것이다.

## 3. 가설

> **완료된 단계의 본문을 접지 않은 채 `PLAN.md` 를 통째로 읽히면, 같은 문서를 접어서 읽힐 때보다
> 후속 세션이 「현재 단계가 폐기한 옛 결정」을 구현하는 빈도가 높아진다.**

**반증 조건**: 두 조건의 통과 수가 같거나 접지 않은 쪽이 더 높으면 가설을 버린다. 그 경우
「접기는 정확도를 위한 조치가 아니라 토큰을 줄이는 조치일 뿐」이라고 결론에 적는다.

이 가설은 **동어반복이 아니다.** 접은 문서에서 옛 결정을 지우지만, **현재 규칙은 두 조건 모두에
완전히 적혀 있다.** 접지 않은 문서도 옛 결정 옆에 「1단계 D2 폐기」라고 명시한다. 문서를 제대로
읽는 에이전트라면 두 조건 모두에서 맞혀야 한다. 틀린다면 그것이 컨텍스트 관리의 효과다.

**「한 모델에서 난 포맷 차이가 다른 모델에서 사라졌다」** 는 사실이 내 실험의 일반화 한계를
그대로 예고하기 때문이다. 나도 모델 하나로만 잰다.

**인용 출처의 한계**: 위 [학술] 수치는 이 모듈의 강의노트를 거쳐 인용했고, **원논문을 직접 열어
대조하지 않았다.** 재검토 조건에 넣는다.

### 고정 / 조작 / 측정

| **측정** | ① **해결률** — 보류해 둔 pytest 통과 여부 ② **토큰** — `input + cache_creation + cache_read`, `output` ③ **승인 횟수** — `permission_denials` 수와 `num_turns` ④ **시간** — `duration_ms`, 벽시계 |

### fixture 3개 (내용을 바꾸지 않는다)

문서 두 벌은 **세 fixture 가 공유**한다. 과업만 다르다.

| fixture | 과업 | 완료 절의 옛 결정 (full 에만) | 현재 절의 규칙 (양쪽 공통) |
|---|---|---|---|
| **f1** | `src/chunk_id.py` 의 `make_chunk_id` | **D2** 청크 ID = `{doc}-p{page}` | **D7** `{doc}-p{page}-c{idx}`, 0 채움 없음 |
| **f2** | `src/emit.py` 의 `emit` | **D5** JSON 배열 하나 | **D8** NDJSON, 마지막 줄 개행 없음, 빈 목록은 빈 문자열 |
| **f3** | `src/config.py` 의 `load_config` | **D4** 환경변수 `OLLAMA_URL` | **D9** `LLM_BASE_URL`, 옛 이름 폴백 없음, 없으면 `KeyError` |

**채점 테스트는 에이전트에게 주지 않는다.** SWE-bench 의 `FAIL_TO_PASS` 처럼 실행이 끝난 뒤에만
작업 폴더로 복사해 돌린다. 테스트를 주면 문서를 읽지 않고도 정답을 맞힐 수 있어 조작이 무의미해진다.

**셀 순서는 고정 시드(20260903)로 섞는다** — 순서 효과를 제거하되 재현 가능하게.

## 6. 사전 판정식 (결과를 보기 전에 확정)

반복 2회 기준. fixture 당 조건별 통과 수는 0·1·2 중 하나다.

| 판정 | 조건 |
|---|---|
| **지지** | 3 fixture 중 **2개 이상**에서 `folded 통과 수 > full 통과 수` |
| **기각** | 위를 만족하지 못하는 모든 경우. 특히 2개 이상 fixture 에서 `full ≥ folded` 면 명확한 기각 |
| **판정 불가** | 2개 이상 fixture 에서 **양 조건 모두 0/2** (fixture 난이도 문제) 또는 `is_error` 셀이 2개 이상 |

**부수 지표는 판정에 넣지 않는다.**

- **토큰**: `folded` 가 적을 것이 거의 확실하다 — 문서가 짧으니 당연하다. **이것을 가설의 지지
  근거로 쓰지 않는다.** 절감량만 기록한다.
- **승인 횟수**: 헤드리스에는 사람이 누르는 승인 창이 없다. `permission_denials` 는 **0 이 나올
  가능성이 높고**, 그러면 「이 실험은 승인 지표를 재지 못했다」로 남긴다. 대리물임을 숨기지 않는다.
- **시간**: 기록하되 판정에 넣지 않는다. 헤드리스 지연은 네트워크에 크게 흔들린다.

**단일 실행으로 읽지 않는다.** m05 에서 얻은 교훈 그대로다 — 「셀당 1회로 잰 축 차이를 효과라고
쓰지 마라」(`m05/PLAN.md:466`). 파일럿 1회는 **소요 시간·사용량 교정용**이며 판정에 쓰지 않는다.

## 7. 예상 반론과 통제 조건

| # | 반론 | 이 반론과 가설을 구분할 통제 |
|---|---|---|
| 1 | **「접으면 옛 규칙이 사라지니 당연히 맞는다」** (동어반복) | 접은 문서에도 **현재 규칙 전문이 그대로** 있고, 접지 않은 문서는 옛 결정 옆에 「폐기」를 명시한다. 두 조건 다 정답이 문서에 있다. 그런데도 차이가 나면 그것은 **문서를 읽어 내는 능력의 차이**이지 정보 유무가 아니다 |
| 2 | **「모델이 문서를 안 읽고 함수 이름만 보고 맞혔다」** | 정답은 파일명·시그니처에서 추론할 수 없다 (`{idx}` 자리, NDJSON 개행 규칙, 새 환경변수 이름은 문서에만 있다). trace 에 최종 응답을 남겨 확인한다 |
| 3 | **「길이가 아니라 옛 문장의 존재가 원인」** | **이 설계는 둘을 분해하지 못한다.** 접기는 길이와 옛 문장을 동시에 바꾼다. 분해하려면 세 번째 조건(긴 문서 + 옛 문장 제거)이 필요하고 그러면 조작이 둘이 된다. **다음 실험의 몫으로 남긴다** |
| 4 | **「sonnet 하나의 결과다」** | 배제하지 못한다. Aider 의 GPT-3.5/GPT-4 사례가 정확히 이 위험을 보여 준다. **미확인으로 남기고 재검토 조건에 넣는다** |
| 5 | **「fixture 가 실물보다 훨씬 짧다」** | 실물은 완료 : 현재 ≈ 19배, fixture 는 5.6배다. **조작 강도가 실물보다 약하다.** 효과가 없게 나오면 강도 부족을 배제할 수 없다 — 결론에 그렇게 적는다 |

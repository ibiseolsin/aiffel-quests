# PRD — agent m02 하네스 개선 실험 보고서

> **작성 순서에 대한 사실**: 이 파일은 실험 실행 **뒤에** 리포 규약(`CLAUDE.md`)을 맞추려고
> 썼다. 실제 순서는 `README.md` 요구사항 정리 → fixture·사전 판정식 확정·커밋 → 실행 →
> 보고서였다. 앞섰던 척하지 않는다. 다음 퀘스트는 PRD 부터 시작한다.

## 누구의 어떤 불편인가

**나(리포 소유자)** 가 `aiffel-quests` 에서 슬라이스를 세션에 하나씩 맡길 때, 후속 세션이
**이미 폐기된 결정을 현재 규칙으로 읽는** 일이 반복됐다. m05 에서 실제로 났고
(`FINDINGS.md` 9절 결론 반전), 대응으로 `PLAN.md` 에 「다음 세션이 잘못 판단하기 쉬운 것 셋」
절을 손으로 넣어야 했다.

## 유즈케이스

1. **U1** — 내 불편 하나를 반증 가능한 가설로 바꾸고, 결과를 보기 전에 판정 기준을 못박는다
2. **U2** — 한 항목만 조작하는 실험을 설계하고, 조작이 실제로 전달됐는지 검증한다
3. **U3** — 실제로 돌려 해결률·토큰·승인 횟수·시간을 실측한다
4. **U4** — 결과가 가설과 달라도 감추지 않고, 무엇이 원인 설명을 약하게 했는지 적는다
5. **U5** — 심사자가 저장소만 보고 재현할 수 있게 fixture·러너·원자료를 남긴다

## 안 할 것

- **도구 비교** — 하네스 우열표를 만들지 않는다. 내 병목 하나만 본다
- **여러 항목 동시 조작** — 길이와 폐기 표기를 함께 바꾸지 않는다 (다음 실험의 몫)
- **모델 여러 개** — sonnet 하나로 고정하고, 모델 의존성은 미확인으로 남긴다
- **실물 저장소에서의 실행** — m05 를 다시 돌리지 않는다. 통제 불가능한 변인이 너무 많다
- **벤더 수치 재현** — 논문·벤더 벤치마크를 다시 돌리지 않는다. 근거로만 인용한다
- **LMS 제출 대행** — 저장소 URL 제출은 사용자가 직접 한다

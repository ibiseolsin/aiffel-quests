## 만들 것

'AI 최신소식' 을 입력하면 자료를 조사하고, **사용자의 선택을 받아** 카드뉴스를 완성하는 웹 앱.

LMS 가 제공하는 **카드뉴스 워크플로 설계 키트(PRD v5.0.0)** 를 개발 도우미에게 통째로 넘겨 일곱 단계
흐름을 먼저 구현하고, 그다음 입력 자료·AI 의 판단·사람의 결정·최종 산출물을 바꾸어 **내가 자주 하는
작업으로 확장**한다.

일곱 단계: 주제 입력·넓은 조사 → 정보 선택 → 심층 조사·편집 판단 → 스토리보드 검토 →
이미지·글자 제작 → 검수·부분 수정 → 승인·내려받기.

## 정해야 하는 것 (개발 도우미가 먼저 묻게 한다)

| 결정 | 선택지 |
|---|---|
| 구현 언어 | Python · TypeScript · Rust 등 자유 |
| 실행 엔진 | Claude Agent SDK / Claude CLI / OpenCode CLI **중 하나** (셋 다 연결할 필요 없다) |
| 검색 수단 | 실제 계정에서 사용 가능한지 확인 |
| 카드 비율 | 참고 구현은 1080×1350 |
| 결과 보관 위치 | — |

엔진별 연결과 세션 이어가기:

| 선택 | 연결 | 이어가기 |
|---|---|---|
| Claude Agent SDK | 코드에서 `query()` 호출 | `options.resume` 에 세션 ID |
| Claude CLI | 서버에서 `claude -p` 실행, JSON 읽기 | `--resume` 에 세션 ID (`--continue` 는 **최근** 세션을 고른다) |
| OpenCode CLI | 서버에서 `opencode run --format json` 실행 | `--session` 에 세션 ID |

> 원시 출력 필드가 다르다 — Claude 는 `session_id`, OpenCode 는 줄마다 이벤트에 `sessionID`·`part.text`.
> **두 엔진 출력을 같은 JSON 이라고 가정하면 안 된다.**

## 제출물

- **구현 결과** — 실행할 수 있는 앱 또는 프로젝트와 간단한 실행 방법
- **PRD 의 결정** — 해결할 불편, 기대 산출물, 사람이 결정하는 지점을 반영한 PRD
- **실행 증거** — 실제 입력부터 선택과 결과까지 확인할 수 있는 화면·기록·산출물
- **실패와 개선** — 기대와 달랐던 사례 하나와 바꾼 점, 다시 실행한 결과. 해결하지 못했다면 남은 문제와
  다음 수정 방향

제출 폴더에 모을 파일: `README.md`(실행 방법) · `PRD.md` · `DECISIONS.md`(선택 이유) ·
`API_SPEC.md`(화면과 서버의 약속) · 실행 화면·결과 파일 · 검증 기록.

## 완료 판단 (원문)

① **실제 자료로 카드뉴스 한 편 내려받기** ② **질문 대기와 실패 후 재개 확인**
③ **내 작업에 맞게 바꾼 흐름 실행**

- **카드뉴스 한 편의 검수까지 끝낸 뒤 확장을 시작**한다. 확장에서는 **정상 입력 한 번과 자료 부족 입력
  한 번**을 실행한다
- 확장이 끝나지 않았다면 **카드뉴스 실습의 완료 범위와 확장의 미완료 범위를 따로 제출**한다
- 한도·인증으로 막히면 모의 자료로 화면 작업을 계속하되 **실제 조사·생성의 미완료 여부를 기록**한다
- **참고 구현을 그대로 제출하지 않는다** — 내 선택에 따라 무엇이 달라졌고 실제로 어떻게 동작했는지 설명
- **기능 수를 늘리기보다 다음 작업에서도 다시 쓸 수 있는 흐름을 완성**하는 데 집중한다

## 검증 항목 (원문 표)

**단계별로 남길 증거**

| 확인 단계 | 증거 |
|---|---|
| 화면 연결 | 모의 자료 표시, 후보 선택, 새로고침 후 유지되는 질문 화면 |
| 실제 엔진 연결 | 검색·원문 읽기 기록, 선택한 후보, 답변이 반영된 원고 |
| 제작 연결 | 실제 생성 이미지 한 장, 스토리보드 승인 후 제작된 카드 5장 |
| 수정·내보내기 | 카드 하나의 수정 전후, 나머지 카드 유지 여부, 내려받아 연 ZIP |

**질문·재개 재현** (모의 오류로 확인해도 된다. 실제 엔진으로 확인한 것과 **구분해 기록**)

| 상황 | 기대 결과 |
|---|---|
| 독자 질문 뒤 새로고침 | 질문·선택지가 남고 답변 전 제작이 시작되지 않는다 |
| 같은 답변 두 번 제출 | 한 번만 시작, 중복 답변은 재실행하지 않는다 |
| 이전 질문 화면에서 뒤늦게 답변 | 지난 질문임을 알리고 현재 작업을 덮어쓰지 않는다 |
| 생성 실패 후 재시도 | 실패 원인 표시, 확정한 기획·성공한 카드 보존 |
| 서버 재시작 후 프로젝트 열기 | 저장한 질문·결과 복원, 재개 또는 재시도 가능 |

관찰 기록은 **입력·조작 / 기대 결과 / 실제 결과 / 수정 후 결과** 네 칸.

**최종 검수** — 최신성과 사실 / 독자와 흐름 / 생성 결과(파일이 실제로 열리는가) / 편집과 가독성 /
실패와 재시도 / 내보내기. **자동 게시까지 진행하지 않고 검수한 파일을 결과물로 제출한다.**

## 주의할 함정 (원문이 명시한 것)

- **개발 도우미 ≠ 실행 엔진** — 전자에 로그인했다고 후자가 인증되지 않는다
- **새로고침 ≠ 서버 재시작** — 서버를 다시 시작하면 메모리에서 기다리던 SDK 콜백은 사라진다.
  **세션 ID 만 저장한다고 화면 상태와 작업이 자동 복구되지 않는다**
- **요청 성공 ≠ 결과 존재** — 종료 코드·응답 문장으로 이미지 생성 성공을 판단하지 말고 **파일까지 검증**
- **참고 구현(v5.1.5) ≠ 목표 PRD(v5.0.0)** — 참고 구현은 독자 질문을 항상 만들고, 제목·본문을 바꾸면
  삽화가 다시 생성될 수 있다. **'이미 알려 준 독자는 다시 묻지 않기' 와 '텍스트만 고칠 때 그림
  유지하기' 는 내 앱에서 별도로 보완할 항목**이다
- **`--dangerously-skip-permissions`** 는 이미지 도구만이 아니라 **그 실행의 모든 도구 요청을 자동
  승인**한다. 웹 서비스에 연결할 때는 **필요한 도구만 허용하는 규칙을 우선** 쓴다
- `need_input` 은 **공식 CLI 필드가 아니라 이 앱이 정하는 규약**이다

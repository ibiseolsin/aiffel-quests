# PRD — 근거를 남기는 개인 하네스 (`my_harness`)

- 상태: D01~D07 **CHOSEN**, D08·D09 **DEFERRED** (`DECISIONS.md`)
- 대상 사용자: 나 (아이펠 수강생, 로컬 Windows 개발 환경)
- 제품 한 줄: **자연어 요청 하나를 받아, 내가 허용한 폴더 안에서만 모델이 도구를 쓰게 하고,
  무엇을 읽고 무엇을 바꿨는지 사람이 되짚을 수 있게 남기는 CLI 하네스.**

## D01 사용자와 업무

- 나는 **수강생**으로서 **과제 폴더의 작은 텍스트·코드 fixture** 에 대해 두 가지를 하고 싶다.
  1. 자료를 읽고 **근거가 붙은 요약**을 얻는다 (범용 자료 작업)
  2. **실패하는 테스트를 고친다** — 테스트는 건드리지 않고 (코딩 작업)
- 지금 불편한 점: 완성된 에이전트 CLI 에 맡기면 **어떤 파일을 실제로 읽었는지, 어느 도구가 실패했는지,
  왜 멈췄는지**가 남지 않는다. 결과만 있고 근거가 없어서 틀렸을 때 원인을 짚을 수 없다.
- 실제로 성공했다고 판단할 결과:
  - 최종 답에 나온 사실이 **도구 기록에 있는 파일 내용과 일치**한다 (지어낸 값이 없다)
  - 파일 변경은 **내가 diff 를 보고 승인한 뒤에만** 적용되고, 지정한 테스트가 실행되어 통과한다
  - 실패했으면 **어디서 멈췄는지**(단계 한도·시간 한도·도구 오류·연결 실패)가 종료 상태로 구분된다
- 실습용 자료: `fixtures/` 의 작은 민감하지 않은 사본 — 모임 공지 텍스트 하나, 결함이 있는 계산 코드와
  그 테스트 하나. 개인 자료·키는 넣지 않는다.

## 공통 요구사항 (R01~R08) 구체화

| ID | 제품이 해야 할 일 | 이 프로젝트에서 구체화한 내용 |
|---|---|---|
| R01 | 요청을 받고 진행·완료·실패를 구분한다 | CLI `run_harness.py --prompt` 한 번 = 작업 하나. 종료 상태 8종을 구분해 표준출력과 `runs/<id>/events.jsonl` 에 남긴다: `completed` `step_limit` `tool_limit` `timeout` `context_limit` `provider_error` `failed` (거절은 종료 상태가 아니다 — 그 도구 호출만 실패시키고 반복을 계속한다) |
| R02 | 모델→도구 요청→검사→실행→결과 반환을 **직접 구현** | `my_harness/loop.py` 의 `Harness.run()`. 한도: 모델 12회·도구 30회·전체 300초·도구당 30초·도구 출력 16,000자·대화 200,000자. 오류 정책은 R07 표를 따른다 |
| R03 | 허용한 자료를 읽고 근거를 확인할 수 있는 결과 | 첫 도구 `list_files`·`read_file`. 작업 폴더는 `--workspace` 하나. 결과 형식: 최종 답 + `읽은 파일 목록` + 종료 이유를 한 화면에 표시. 실행 시작 시 하네스가 작업 폴더를 관측해(`orientation.brief`) 첫 메시지에 실제 파일 목록을 넣는다 |
| R04 | 코드 변경을 보여 주고 제한된 테스트로 검증 | `write_file` 은 통합 diff 를 표시하고 승인을 받는다. `run_tests` 는 **`--test-target` 로 미리 고정한 unittest 대상만** 실행한다 (모델이 대상을 바꿀 수 없다) |
| R05 | 권한 없는 경로·승인 없는 변경을 막는다 | 경로 검사는 도구 코드 안에서 모델 지시와 무관하게 적용 (절대경로·`..`·숨김·심링크·폴더 이탈 거부). 승인 단위는 **파일 하나의 변경 내용 하나**. 거절하면 그 도구 호출만 실패로 모델에 돌려주고 작업은 계속한다 |
| R06 | 실행 기록과 세션을 구분하고 이어갈 범위를 설명 | 세션은 `sessions/<name>.json` 에 **파일로 영속**. 저장 항목은 모델에 보이는 대화(도구 인자·결과 포함)와 세션 설정. 재시작 후 같은 `--session` 이름이면 복원한다. 설정(provider·model·workspace)이 다르면 복원을 거부한다. **키는 저장하지 않는다** |
| R07 | 모델 제공자와 내부 계약을 분리 | `my_harness/providers.py` 의 `OllamaProvider` 가 네이티브 `/api/chat` 을 내부 계약(`ModelTurn`)으로 변환한다. 내부 계약은 제공자 필드를 모른다 |
| R08 | 고정 10문항 기준·변경 후 측정과 비교 | `my_harness/benchmark_adapter.py` 의 `solve_task` 로 `agent-terminal-benchmark` v1.0.0 (평가 `terminal-bench-pro-local-port-v2`) 에 연결. 두 실행의 모델·한도·문항·평가 버전을 고정하고 하네스 코드만 바꾼다 |

### R07 오류 구분 (A07 이 검증하는 표)

| 원인 | 처리 | 사용자에게 |
|---|---|---|
| 도구 인자 오류 (스키마 위반·경로 이탈·없는 파일) | `{"ok": false, "error": ...}` 를 **모델에 반환**하고 반복을 계속한다 | 도구 실패로 표시, 작업은 계속 |
| 등록되지 않은 도구 이름 | 같음 (모델에 반환) | 같음 |
| 승인 거절 | 같음 (모델에 반환) — 파일은 그대로 | 거절했다고 표시 |
| 모델 API 연결 실패 (연결 거부·HTTP 오류·응답 파싱 실패) | 반복을 **중단**한다 | 종료 상태 `provider_error` 와 예외 종류를 표시. **성공으로 기록하지 않는다** |

## 최초 범위와 제외 범위

- 최초 범위: CLI 한 개, 도구 5개(`list_files` `read_file` `write_file` `run_python` `run_tests`),
  Ollama 제공자 1개, 파일 세션, diff 승인, 한도·오류 정책, 벤치마크 어댑터.
- 이번 버전에서 제외:
  - **추가 제공자(D08)** — `OPENAI_API_KEY` 가 없어 **실행으로 검증할 수 없는 코드를 넣지 않는다.**
    구조상 자리는 비워 뒀다(`providers.py` 의 `Provider` 프로토콜). → A10 `DEFERRED`
  - **취소·동시 실행·원격 접속(D09)** — 첫 버전 범위 밖. 진행 이벤트(JSONL)만 넣었다.
  - 임의 셸 명령 — `run_python`(작업 폴더 안의 `.py` 파일)과 `run_tests`(고정 대상)만 허용한다.
- 기본 제외: 공개 원격 제어, 시스템 전체 접근, 비밀키 공유.

## 벤치마크 실험 (R08)

- 고정 10문항: easy 2 · medium 4 · hard 4. 난도는 원본 `task.toml` 그대로.
- 두 실행 `own-baseline` / `own-improved` 는 **모델·한도·문항·평가 버전을 동일**하게 두고
  `my_harness` 코드만 바꾼다. 바뀐 것은 `EXPERIMENT_REPORT.md` 에 diff 로 적는다.
- 분모는 **10 고정**. 오류·미완료를 빼지 않는다. 비이진 보상은 부분 점수 없이 오류로 표시한다.
- `--self-check`(채점기 진단)와 내 `pytest` 통과는 **점수가 아니다.**

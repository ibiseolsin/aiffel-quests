## 만들 것

세 실행의 결과 파일을 근거로 한 **채택·축소·폐기 판정문**.

세 실행의 유일한 차이는 **다음 행동을 정하는 주체**다. 문제·모델 별칭·저장소 준비·채점 조건은 고정한다.

| 실행 | 다음 행동을 정하는 주체 | 흐름 | 턴 예산 |
|---|---|---|---|
| **A** 기준선 | 한 에이전트 | 질문 → 에이전트 1회 → 결과 | 25 |
| **B** 워크플로 | 파이썬 코드 | locator(읽기 전용) → 보고서 → fixer | 12 + 18 |
| **C** 오케스트레이션 | 리드 모델 | 리드 판단 → locator 선택 호출 → 직접 수정 | 40 |

## 원문 기준 요구사항

### 과제의 목표

1. **비교할 조건을 분리합니다.** 고정할 조건, 바꿀 조율 방식, 측정할 값을 실행 전에 구분합니다.
2. **결과 파일에서 근거를 읽습니다.** `result.json` 의 실행 결과와 `grading.jsonl` 의 판정 근거,
   `results-table.md` 의 비교 행을 연결해 읽습니다.
3. **결론의 범위를 정합니다.** 이 실험 조건에서 채택·축소·폐기 가운데 하나를 고르고, 다시 확인할
   조건을 밝힙니다.

### 평가 루브릭

각 루브릭은 제출물에서 다음이 확인될 때 충족이다.

- [ ] **고정·조작·측정이 분리되어 있습니다.** 같은 인스턴스·모델·저장소 준비·채점 조건과 기준선
      실행(A)·워크플로 실행(B)·오케스트레이션 실행(C)의 조율 방식을 구분했고, 해결 여부·비용·턴·
      경과 시간·행동 판정을 측정값으로 제시했습니다.
- [ ] **결과 파일의 근거가 연결되어 있습니다.** `result.json`, `grading.jsonl`, `results-table.md`
      에서 확인한 행 또는 인용을 판정문과 연결했고, `evidence_quote` 는 원래 전사로 다시 확인했습니다.
- [ ] **결론의 적용 조건이 분명합니다.** 턴 예산 차이와 경량 평가라는 한계를 밝히고, 이 조건에서만
      채택·축소·폐기 결론을 말했습니다.

### 판정문 형식 (원문 그대로)

> "이 조건에서는 [채택·축소·폐기]합니다. [결과 파일의 근거]가 있고, [비용·시간·턴 또는 판정
> 기록]이라는 한계가 있기 때문입니다."

재실행한다면 고정할 조건과 바꿀 조건을 함께 적는다.

## 채점 두 층

| 층 | 내용 |
|---|---|
| ① 결정론적 | 테스트 패치 적용 후 pytest 종료 코드를 **직접** 받는다 → `resolved`. `tests/` 아래를 건드렸으면 `invalid` |
| ② LLM judge | 세션 JSONL 전사를 읽어 **근거_추적 · 편집_최소성 · 검증_성실성**을 0·1·2 로. `json_schema` 가 세 점수 + MAST 계열 실패 분류 + **`evidence_quote` 필수**를 요구 |

실패 분류에는 턴_소진 · 무근거_편집 · 과잉_편집 · 검증_생략 등이 포함된다.

## 함정 (원문이 명시한 것)

- **`pytest | tail` 로 판정하지 않는다** — 파이프가 pytest 실패를 `tail` 의 종료 코드 0으로 가린다.
  출력을 줄이는 처리와 실패를 판정하는 처리를 분리한다
- **턴 예산이 다르므로** 해결 여부·비용·시간만 나란히 놓고 구조의 효과라고 해석할 수 없다
- **서브에이전트를 정의했다는 사실만으로 분업이 일어났다고 볼 수 없다** — C에서 리드가 locator 를
  실제로 불렀는지 `evidence_quote` 로 확인한다
- **결과 파일을 덮어쓰지 않는다** — 이전 기록과 비교할 수 없게 된다. 러너는 `result.json` 이 있는
  실행을 건너뛴다
- **`evidence_quote` 가 실제 전사에 없으면** 점수도 신뢰할 수 없으므로 원래 기록으로 돌아간다
- 코딩 에이전트에게 위임하면 **요약을 결과로 받아들이지 말고** 실제 명령과 결과 파일을 확인한다

## 착수 전에 채워야 하는 빈칸

강의노트 「열린 질문」과 같은 항목이다. 원문에 없어서 저장소를 받거나 직접 정해야 한다.

- `SYS_A` · `SYS_B_LOCATE` · `SYS_B_FIX` · `SYS_C` 의 시스템 프롬프트 본문
- 4강의 인스턴스 단건 실행 명령 — **원문 페이지의 해당 코드 블록이 비어 있다**
  (5·6강 용법에서 `arms.py <실행> <인스턴스>` 형태로 짐작됨)
- 정확한 모델 ID (원문에 "haiku", "haiku4.5", `anthropic/claude-haiku-4-5` 가 섞여 등장)
- `results-table.md` 에 "미리 실어 둔 실측값" 의 실제 내용
